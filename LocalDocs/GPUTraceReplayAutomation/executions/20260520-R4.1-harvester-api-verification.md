## 2. 核心发现

### 2.1 Harvester 函数本质

Harvester 函数是**纯离线 blob 解析器**，直接操作 .gputrace bundle 中存储的资源文件：
- **不依赖** replay 运行时状态
- **不依赖** APR bootstrap
- **不依赖** Metal device
- 仅需 dlopen 框架 + dlsym 获取函数指针即可

### 2.2 数据格式

纹理资源 blob 结构（"capture" 格式）：

```
Offset  Size  Field
0x00    8     Magic: "capture\0" (LE: 0x0063617074757265)
0x08    2     Version major (02 00)
0x0A    2     Version minor (01 00)
0x0C    4     Pixel format indicator (e.g. 0x00010000)
0x10    8     Unknown (plane count related?)
0x18    8*N   Plane descriptors (per-plane: format, width, height, depth?, bytesPerRow?)
...
0x100   ...   Raw pixel data (texture payload)
```

- Header: 256 bytes (0x100)
- Payload: 从 +256 开始到 EOF

### 2.3 函数签名（逆向确认）

```c
// 返回指向 blob+0x100 的指针（跳过 header，指向原始纹理数据）
// 对无 magic 的 buffer blob 也返回 blob 起始（直接作为数据）
void* GTHarvesterGetData(const void *blob, uint64_t blob_size);

// 返回 metadata 指针（对 capture blob 为 blob 起始，对非 capture 返回 NULL）
void* GTHarvesterGetMetadata(const void *blob, uint64_t blob_size);

// 返回 blob+24 处第 plane_index 个 plane 描述符的指针
// plane 描述符包含 format/width/height/depth/bytesPerRow 信息
void* GTHarvesterGetTexturePlane(const void *blob, uint64_t plane_index);

// 读取 blob+0x0A 处的 uint16，若 < 2 则返回 blob+16 处的值，否则返回 blob+16
uint64_t GTHarvesterGetTexturePlaneCount(const void *blob);
```

### 2.4 参数验证逻辑

`GTHarvesterGetData` 内部验证流程：
1. `CBZ x0` — blob 为 NULL 则立即返回 NULL
2. `CMP x1, #0x10` — blob_size < 16 则返回 NULL
3. 读取 `blob[0:8]`，与 magic `0x0063617074757265` 比较
4. Magic 不匹配时：走另一条路径（直接返回 blob 指针，适用于 buffer 类原始数据）
5. Magic 匹配时：验证通过，读取内部偏移字段计算数据起始位置

## 6. 对后续任务的启示

1. **Harvester 是完全离线工具** — 不需要启动 replay，可以直接读取 .gputrace 中的存量资源。适合做批量资源提取/分析。

2. **"capture" 格式 header** 包含完整的纹理 metadata（format、dimensions、plane count），可用于构建资源索引。

3. **R4.2 / R4.3 的必要性被重新定义**：
   - Harvester 解决了 **已截帧数据的离线提取**
   - Host/Controller 路径用于 **replay 运行时的实时数据获取**（如：replay 到某个 draw call 后看当前 render target）
   - 两者互补而非替代

4. **建议新增子任务**：R4.1b — 解析 "capture" header 完整字段语义，构建 JSON metadata 导出能力。
