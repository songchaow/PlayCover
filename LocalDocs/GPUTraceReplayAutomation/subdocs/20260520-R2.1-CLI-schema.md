# R2.1 技术参考：gputrace_bridge.py CLI / JSON Schema 设计

**完成时间**：2026-05-20  
**结论**：统一入口 `gputrace_bridge.py` + 子命令模式，纯 Python 3.9+ 标准库

---

## 1. 顶层结构

```
gputrace_bridge.py <subcommand> [options]

子命令：
  scan-active-replay   观察当前活动 replay 进程与文件访问
  scan-binaries        扫描 Xcode 私有二进制模块
  inspect-gputrace     检查 .gputrace bundle 结构与 metadata
```

### 公共选项

| 选项 | 默认 | 说明 |
|------|------|------|
| `--json` | ✅ | JSON 输出 |
| `--pretty` | off | 缩进格式化 |
| `--quiet` | off | 抑制 stderr |
| `--xcode-path` | 自动检测 | 覆盖 Xcode 路径 |

---

## 2. scan-active-replay

观察系统中 GPU replay 相关进程及文件访问。

**选项**：`--include-lsof`(default true), `--filter-pid PID`

**输出核心字段**：
- `replay_active`: bool
- `processes[]`: pid, name, path, role(xcode|replay_service|compat_service|agent_service|llvm_helper|other), open_files[]
- `open_files[]`: fd, path, category(gputrace_store|gputrace_resource|metal_cache|metallib|other)
- `active_gputrace_path`, `metal_cache_dir`

---

## 3. scan-binaries

静态扫描 Xcode 内 GPU 私有模块。

**选项**：`--modules MODULE,...`, `--symbols`, `--strings PATTERN`

**输出核心字段**：
- `xcode_path`, `xcode_version`
- `modules[]`: name, path, exists, arch[], size_bytes, key_symbols[], matched_strings[]
- key_symbols[]: name, type(function|class|ivar|global|other), visibility(exported|local|undefined)

**预设关键符号锚点**：

| 模块 | 符号 |
|------|------|
| GPUToolsReplay | `GTMTLReplay_CLI`, `GTMTLReplayController_makeDataSource`, `GTHarvesterGetAPIStatistics`, `g_runningInCI` |
| GPUToolsServices | `DYCaptureSession`, `DYGuestAppSession`, `_kDYGuestAppLaunchReplayer` |
| GPUDebugger | `GPUTraceShaderProfiler`, `GTHostMTLCounterSampleBuffer` |

---

## 4. inspect-gputrace

检查 .gputrace bundle 结构与 metadata。

**选项**：`PATH`(必填), `--include-sizes`(default true), `--include-metadata`(default true)

**输出核心字段**：
- `valid`: bool, `total_size_bytes`
- `metadata`: uuid, captured_frames_count, graphics_api, capture_version, device_id, native_pointer_size, boundary_less, interpose_feature_version, library_link_time_versions, unused_resource_counts
- `files[]`: name, type(store|resource|platform|index|metadata|capture|other), size_bytes, is_directory

---

## 5. 错误输出

统一格式：`{error: {code, message, context}}`

错误码：`NO_REPLAY_ACTIVE`, `XCODE_NOT_FOUND`, `MODULE_NOT_FOUND`, `GPUTRACE_INVALID`, `GPUTRACE_NOT_FOUND`, `PERMISSION_DENIED`, `LSOF_FAILED`, `INTERNAL_ERROR`

---

## 6. 文件/进程分类规则

### gputrace 文件分类
- `store*` → store | `*device-resources*` → resource | `startup-*-platform` → platform
- `index` → index | `metadata` → metadata | `capture`/`unsorted-capture` → capture | 其它 → other

### lsof 文件分类
- `*/store*` → gputrace_store | `*device-resources*`/`*startup-*` → gputrace_resource
- `*/functions.*`/`*/libraries.*`(metal 缓存目录) → metal_cache | `*.metallib` → metallib | 其它 → other

### 进程角色
- Xcode → xcode | GPUToolsReplayService → replay_service | GPUToolsCompatService → compat_service
- GPUToolsAgentService → agent_service | GTLLVMHelper → llvm_helper | 其它 → other

## 7. 实现约束（面向 R2.2）

- 单文件 `Scripts/gputrace_bridge.py`，纯 Python 3.9+ 标准库
- 必须包含 `--dry-run` 模式
- `lsof` 失败时不终止，仅 stderr warning + open_files 置空
- 测试策略：scan-active-replay 验证字段完整性；scan-binaries 验证符号发现；inspect-gputrace 用离线样本验证 metadata
