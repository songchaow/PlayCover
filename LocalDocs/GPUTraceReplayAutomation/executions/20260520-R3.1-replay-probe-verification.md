## 3. 关键发现：APR Bootstrap 问题

### 问题

`GTMTLReplay_CLI` 内部第一步调用 `apr_pool_create_ex()`（Apache Portable Runtime 内存池），该函数依赖已初始化的全局 pool。正常路径由 `GPUToolsReplayService.xpc` 的 `main()` 在调用 CLI 前完成初始化。

### 崩溃分析

```
EXC_BAD_ACCESS at apr_pool_create_ex + 64
原因：全局 pool 指针为 NULL → 尝试解引用 NULL+0x30 获取 allocator
```

### 解决方案

通过导出符号 `GT_ENV` 定位全局 pool 指针位置（GT_ENV - 0x30），手动构造：
1. **allocator 结构体**（0xC8 bytes）：`[0x00]=max_index(20), [0x08]=max_free_index(20), [0x18]=NULL(mutex)`
2. **fake global pool**（0x80 bytes）：`pool[0x30] = allocator`
3. 将 global pool 指针写入框架 BSS 段的全局变量

### 关键偏移量（macOS 26.4.1, GPUToolsReplay 314.12）

| 全局变量 | 位置 | 含义 |
|---------|------|------|
| global_pool_ptr | `&GT_ENV - 0x30` | APR 全局 pool 指针 |
| GT_ENV | 导出符号 offset 0x4DA9C3A8 | 框架全局环境变量 |
| g_runningInCI | 导出符号 offset 0x4DA9C3E0 | CI 模式标志 |

### allocator 结构体布局

| 偏移 | 类型 | 含义 | 设置值 |
|------|------|------|--------|
| +0x00 | uint64 | max_index (free list 桶数) | 20 |
| +0x08 | uint64 | max_free_index | 20 |
| +0x10 | uint64 | current_free_index | 0 |
| +0x18 | ptr | mutex (NULL=无锁) | NULL |
| +0x28 | ptr[] | free list 数组 (20个桶) | 全 NULL |

### pool 结构体关键字段

| 偏移 | 含义 |
|------|------|
| +0x00 | allocator 指针 |
| +0x08 | next sibling |
| +0x10 | child list head |
| +0x18 | parent back-link |
| +0x30 | allocator 指针（apr_pool_create_ex 从此处读取） |
| +0x40 | abort_fn |
