## 总体技术路线

## 文档职责

本文只描述 `SemanticsValidation` 的**分层模型、层间关系、止损规则与推荐产物**。

**任务状态、进展、优先级、TODO、完成判定与默认执行顺序统一只在 `00-Dashboard.md` 维护。** 本页不重复动态控制面信息。

## 目标

本目录当前的最终落点已经收口为两件可验证的事：

1. 确保当前现有测试全部通过，重点是 `ShaderCorpus` 与 `ShaderSourceDiagnostics` 两条 full-batch 批量验证通过
2. 确保 `QQ飞车手游` 启动不会崩溃

分层模型仍可作为解释问题、组织证据和排查风险的背景框架；但它**不再代表“后续还要继续收口 `L2/L3 gate`”的执行计划**。

## 基本约束

- 任何新路线都不应把 GUI、人工登录、工作区外修改、人工批量枚举样本或人工准备环境写回默认流程
- 日常构建、调试、测试、验证应优先保持为 agent 可独立完成的命令链路
- 结构化报告应优先作为事实载体；描述文字只能辅助解释，不能替代报告本身
- 高层验证用于补充低层证据，不能反向替代低层职责

## 分层模型（背景参考）

### L1：IR Round-trip 结构验证

目标：建立最小闭环：

```text
IR -> MSL -> AIR -> IR
```

回答的问题：

- 哪些样本能完成 round-trip
- 哪些样本在生成 MSL、Metal 编译或反汇编阶段失败
- 哪些样本可以继续进入结构比较

L1 提供的是**闭环能力与失败分层**，不是语义证明。

### L2：Canonical Compare + 风险分级

目标：把“文本 diff”升级为“结构化 compare + 风险分级”。

重点比较：

- entry 集合与 shader 类型
- 参数/返回摘要
- 地址空间
- builtin / resource 使用
- CFG 粗结构
- instruction family 分布
- fast-math 与关键属性

L2 提供的是**批量可运行的语义风险筛查**，不是行为 oracle。

### L3：最小行为测试

目标：在少量高价值样本上建立“固定输入 → 固定输出”的自动验证。

优先顺序：

1. compute-first
2. 必要时 render-second

L3 用于把结构风险升级为行为证据。

### L4：真实场景验证

目标：在真实 shader、真实 capture、真实 app 场景中做最终后置确认。

L4 解决的是：

- 低层证据是否足够可信
- 某些问题是否只能在 runtime / live 条件下暴露
- replacement / `.gputrace` / render 结构是否真正命中

## 使用原则（背景参考）

### 1. 先守当前完成标准，再决定是否借用更高层信息

当前默认只保留下面几件事作为完工标准：

- 现有测试通过，尤其是 `ShaderCorpus` 与 `ShaderSourceDiagnostics` 的 full-batch 结果
- `QQ飞车手游` 启动不崩
- 自动化边界不回退

`L2 / L3 / L4` 的信息如果能帮助定位问题，可以临时借用；但不要再把它们扩成新的收口 gate 或后续里程碑。

### 2. 分层关系用于解释证据，不等于当前执行计划

可以继续把各层理解为：

```text
L1 -> L2 -> L3 -> L4
```

但当前并不要求沿着这条链继续把 `L2/L3 gate` 单独收口；只有在解释具体 blocker 时，才按需借用更高层信息。

### 3. 先批量，再定向

优先建立可以批量运行、结构化落盘的入口；单样本 smoke、定向 live 复核只适合作为补充动作。

### 4. 先自动化，再人工兜底

任何验证路径都应优先证明：

- 可以本地执行
- 可以脚本化
- 可以稳定落盘
- 不需要用户频繁介入

### 5. 先复用已采集样本，再考虑新增样本

样本优先顺序应是：

1. 固定代表集 / 内置测试样本
2. 本地已存在的 `ShaderCorpus`
3. 本地已导出的 `ShaderSourceDiagnostics`
4. 仅在必要时新增更高成本样本

## 与现有工作流的关系

现有主回路仍然是“真实样本采集 → 离线 replay / compile / diff → 必要时 startup / live 复核”。

`SemanticsValidation` 提供的是一条更早暴露问题的离线证据支路：

```text
module.ll -> round-trip -> canonical compare -> risk grading
```

这条支路当前的职责，是帮助更快发现、解释并回归 `corpus / diagnostics` full-batch blocker；它不是一条还需要额外单独收口的 `L2/L3 gate` 规划。

## 推荐产物结构

```text
build/semantics-validation/
  roundtrip/
    <preset-or-run>/
      replay-summary.json
      compile-summary.json
      roundtrip-summary.json
      compare-summary.json
      risk-report.json
      high-risk-samples.json
      gate-summary.json
      preset-manifest.json
      # optional
      baseline.json
      generated-sources/
  behavior/
    <run>/
      behavior-summary.json
  real-scene/
    <run>/
      live-summary.json
      gputrace-summary.json
      render-diff-summary.json
      diagnostics-summary.json
```
