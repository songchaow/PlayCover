## 2. 实现概览

### 2.1 新增的 swizzle（12 个）

在 R7.3 已有的 9 个 render-encoder swizzle（`setRenderPipelineState:` / 5 × `drawXXX:*` / `endEncoding`）基础上扩展 12 个 `set*` 方法：

| Stage | Selector | Thunk 行为 |
|-------|----------|-----------|
| vertex | `setVertexBuffer:offset:atIndex:` | 更新 `cur_v_buffer_ptr/offset[idx]`，清 `inline_size[idx]` |
| vertex | `setVertexBuffers:offsets:withRange:` | 同上，按 NSRange 批量更新 |
| vertex | `setVertexBytes:length:atIndex:` | 设 `cur_v_inline_size[idx]=len`，清 ptr/offset |
| vertex | `setVertexTexture:atIndex:` | 更新 `cur_v_texture_ptr[idx]` |
| vertex | `setVertexTextures:withRange:` | 同上批量 |
| vertex | `setVertexSamplerState:atIndex:` | 更新 `cur_v_sampler_ptr[idx]` |
| fragment | （6 个 `setFragment*` 对称变体） | 同 vertex |

所有 thunk 共享同一形态：先调原 IMP（保证 framework 状态正确），再在 `g_frame_capture_armed && g_frame_capture_bindings` 双 gate 下更新当前活动 render encoder 的 rolling slot 表（compute/blit encoder 命中 `frame_active_render_encoder` 短路返回 NULL）。

### 2.2 数据结构扩展

```c
// per-encoder rolling state（每 stage 4 张表 × 2 stages = 8 张表）
typedef struct {
    // ...原 R7.3 字段...
    void       *cur_v_buffer_ptr   [MAX_BINDING_BUFFERS];   // 32
    uint64_t    cur_v_buffer_offset[MAX_BINDING_BUFFERS];
    uint32_t    cur_v_inline_size  [MAX_BINDING_BUFFERS];   // 0 = not inline
    uint8_t     cur_v_buffer_set   [MAX_BINDING_BUFFERS];   // bitmask 1=slot ever set
    void       *cur_v_texture_ptr  [MAX_BINDING_TEXTURES];  // 32
    uint8_t     cur_v_texture_set  [MAX_BINDING_TEXTURES];
    void       *cur_v_sampler_ptr  [MAX_BINDING_SAMPLERS];  // 16
    uint8_t     cur_v_sampler_set  [MAX_BINDING_SAMPLERS];
    // ...对称的 cur_f_* 集合...
} FrameEncoderEntry;

// per-draw snapshot (~280 bytes / draw)
typedef struct {
    // ...原 R7.3 字段...
    BOOL                bindings_captured;
    FrameStageBindings  v_bind, f_bind;
} FrameDrawEntry;
```

每次进入 `drawXXX:*` 时（在 `frame_record_draw` 内），如果 `g_frame_capture_bindings == 1`，把 8 张 rolling 表 `memcpy` 到 `FrameDrawEntry.{v,f}_bind` —— 8 次 memcpy ≈ 280 bytes，相对 swizzle 自身开销可忽略。

### 2.3 emit 阶段：O(1) resource_id 解析

`objectMap.resources` 是 NSDictionary `{resource_key (NSNumber) → resource_obj (id<MTLBuffer>/id<MTLTexture>)}`，我们需要反向映射 `obj → key`。每个 binding emit 都做线性扫描（247 资源 × 2776 bindings = 686k 次比较）会显著拖慢输出。

**优化**：在 `cmd_frame_list` 的 emit 阶段一次性反转：

```objc
NSMutableDictionary *resPtr2Id = [NSMutableDictionary dictionary];
for (NSNumber *key in res) {
    [resPtr2Id setObject:key forKey:[NSValue valueWithNonretainedObject:res[key]]];
}
```

之后每个 binding emit 是 O(1) NSValue 查找。LYSK 实测 emit 阶段从原本会 ~600ms（线性扫）降到 ~50ms。

### 2.4 JSON schema

每 render-encoder draw 增加 `bindings` 字段（仅在 `--with-bindings` ON 时）：

```json
{
  "draw_index_global": 0,
  "rps_key": 472,
  "rps_label": "Papegame/Cloth/ClothStandard",
  ...
  "bindings": {
    "vertex": {
      "buffers":  [{"index":0,"resource_id":2,"offset":262144}, ...],
      "textures": [{"index":0,"resource_id":91}],
      "samplers": [{"index":0,"sampler_ptr":"0x12a3e4500"}]
    },
    "fragment": {
      "buffers":  [{"index":0,"resource_id":8,"offset":0}, ...],
      "textures": [{"index":0,"resource_id":186}, {"index":3,"resource_id":211}, ...],
      "samplers": []
    }
  }
}
```

设计选择：
- **稀疏列表**：只 emit `set[i] == 1` 的槽位，空 stage emit 空数组（消费方仍可 `.buffers` 解包）
- **inline bindings**：`setVertexBytes:length:atIndex:` 没有 resource_id，落 `{"index":N,"inline_bytes_size":S}` 不带 `resource_id`/`offset`
- **sampler 没有 resource_id**：sampler state 不在 `objectMap.resources` 里，只 emit `sampler_ptr` 作诊断身份匹配
- **顶层 `with_bindings: bool`** 字段 echo 实际状态（`emit_bindings = with_draws && with_bindings && !no_bindings`）
- **compute/blit encoder 不 emit bindings**：因为它们不 emit 任何 draw record（R7.5-B 之前也不会有）

## 3. CLI / wrapper 接口

### 3.1 bridge

```bash
gputrace_replay_bridge frame-list <.gputrace> [--with-draws] [--no-draws] [--with-timing] [--with-bindings] [--no-bindings]
```

- `--with-bindings` 是默认（与 `--with-draws` 风格一致），显式指定只用于对称性
- `--no-bindings` 抑制 binding 捕获 + 输出（顺手关闭 `g_frame_capture_bindings`，跳过 8 次 memcpy / draw 与 emit）
- 若同时给 `--no-draws`，自动隐含 `--no-bindings`（emit 决策 `emit_bindings = emit_draws && opts.with_bindings && !opts.no_bindings`）

### 3.2 wrapper

```python
from gputrace_replay_wrapper import ReplayBridge
b = ReplayBridge()

# 默认：with_bindings=True
fl = b.frame_list("/path/to/trace.gputrace")
assert fl.with_bindings is True
for cb in fl.command_buffers:
    for e in cb.encoders:
        for d in e.draws:
            if d.bindings:  # render-encoder draws only
                print(d.draw_index_global, "v_bufs:", len(d.bindings.vertex.buffers))

# 抑制
fl_lite = b.frame_list("/path/to/trace.gputrace", with_bindings=False)
assert fl_lite.with_bindings is False
```

新增 dataclass：
- `FrameBufferBinding(index, resource_id, offset, inline_bytes_size)`：互斥两态——资源型（resource_id+offset）或 inline 型（inline_bytes_size）
- `FrameTextureBinding(index, resource_id)`
- `FrameSamplerBinding(index, sampler_ptr)`
- `FrameStageBindings(buffers, textures, samplers)`
- `FrameDrawBindings(vertex, fragment)`

CLI 子命令：`python3 gputrace_replay_wrapper.py frame-list <trace> [--no-bindings]`。

**关键不变量验证**：
- ✅ 244/244 draw 都有 `bindings` 字段（`missing_bindings=0`）
- ✅ 244/244 draw 都有 `vertex.buffers[index=0]`（vb0 不变量——Metal vertex shader stream 入口契约）
- ✅ 244/244 draw 都有 `fragment.textures` 非空（PBR 渲染密度不变量）

## 8. 已知局限（移交 R7.6-B / R7.5）

- **inline buffer 的实际字节内容**：当前只记录 `inline_bytes_size`，不复制实际 bytes（避免污染 binding 表，且 LYSK 0 inline 用例）。如未来需要，可加 `--with-inline-bytes` flag 在 swizzle 内 `memcpy` 到 FrameDrawEntry 的可变长 buffer。
- **sampler 没有 resource_id**：sampler state 不在 `objectMap.resources` 里，只能 emit ptr。如果 sampler 也需要稳定 ID，需另行在 `pipeline` 子命令里枚举 sampler key range（独立工作量，不在 R7.6-A 范围）。
- **uniform/cbuffer 内容解码**（R7.6-B 责任）：R7.6-A 提供 buffer_id + offset，但不解析"buffer N 偏移 0 的 16 字节是 `_MainLightDirection`"这类 cbuffer 布局信息。需 metallib reflection 数据 / `MTLArgumentEncoder` 反射。
- **indirect draw**（R7.3 历史局限）：`drawPrimitives:indirectBuffer:*` 不在 swizzle 集合，LYSK 不用，需要时再加。
- **compute encoder bindings**（R7.5-B 顺带）：`setBuffer:offset:atIndex:` / `setTexture:atIndex:` 在 `MTLComputeCommandEncoder` 上同名但不同 selector slot，目前不捕获；需 R7.5-B 装 compute swizzle 时一起加。
- **Argument buffer 内容**：set\*Buffer 拿到的是 argument buffer 本身，里面的多 slot indirect resources 在 binding 表里看不到（Metal argument buffer 是 GPU-side indirection）；R7.6-B 需要时按 metallib reflection 二级展开。

## 9. 与 R7.6-C 的联动展望

R7.6-C `shader-of-drawcall <draw_index>` 当前透传 `frame-list → draw_to_rps_map[N] → shader-of-rps`，没有把 bindings 放进它的输出。下一步可在 wrapper 层把 frame-list 的 `bindings` 字段附到 `ShaderOfDrawcallResult`（例如新增 `.bindings: FrameDrawBindings | None` 字段），让用户一行命令就能拿到完整三件套：

- shader IR (`.ll` 文件路径)
- bindings (vertex/fragment buffer/texture/sampler 表)
- *uniforms*（待 R7.6-B 落地后补）

这是"draw_index → 完整 draw 上下文"心智的最终形态。本次 R7.6-A 不直接做 wrapper 联动（保持本任务最小变更原则），留 R7.6-B 一并处理。

## 10. 一句话总结

R7.6-A 用对称扩展 R7.3 swizzle 集合的方式（12 个 set\* 方法 + 2 张 stage rolling 表 + 1 张 ptr→resource_id 反向字典）让 `frame-list` 在 244/244 LYSK draw 上同时输出"用了哪段 shader + 绑了哪些 buffer/texture/sampler"，集成测试 102 → 116/116，输出体积 +275%（可控，可 `--no-bindings` 关闭），bridge 0.5.0 → 0.6.0。`shader-of-drawcall` 体验质变；下一步 R7.6-B（uniforms 内容）拿 R7.6-A 的 buffer_id + offset 当输入，再过反射就能输出"draw N 的 cbuffer 实际值"。
