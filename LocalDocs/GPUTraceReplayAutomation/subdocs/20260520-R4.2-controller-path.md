# R4.2 技术参考：Controller 路径 — Headless In-Process Replay Controller

**完成时间**：2026-05-20  
**方法**：V1 静态反汇编 + V4 最小样本测试  
**结论**：✅ Controller 路径完整验证成功。无需 XPC/entitlement，在进程内直接创建 replay controller 并执行 playAll

---

## 1. 完整调用链

```
apr_pool_create_ex(&pool, NULL, NULL, NULL)
    ↓
GTMTLReplayController_makeDataSource(path, pool)
    ↓ → dataSource (APR-based state machine context)
GTMTLReplaySupport_init(device)
    ↓
[[GTMTLReplayObjectMap alloc] initWithDevice:device]
    ↓ → objectMap (302 个方法，管理所有 replay GPU 对象)
GTMTLReplayController_initializeArgumentBufferSupport(dataSource, device, objectMap)
    ↓
GTMTLReplayController_populateUnusedResources(dataSource, objectMap)
    ↓
GTMTLReplayController_makeController(dataSource, pool, device, objectMap, NULL, NULL)
    ↓ → controller (完整 replay controller)
GTMTLReplayController_playAll(controller) → 0
GTMTLReplayController_rewind(controller)
```

## 2. 内部函数偏移表（相对 GTMTLReplay_CLI BL 偏移定位）

| 函数 | CLI 偏移 | 签名 |
|------|----------|------|
| `apr_pool_create_ex` | +0x050 | `int (void **pool, void *parent, void *abort, void *alloc)` |
| `GTMTLReplayController_makeDataSource` | +0x13c | `void* (const char *path, void *pool)` |
| `GTMTLSMContext_getDevice` | +0x230 | `void* (void *context)` |
| `GTMTLReplaySupport_init` | +0x888 | `void (void *device)` |
| `initializeArgumentBufferSupport` | +0x898 | `void (void *ds, void *device, void *objectMap)` |
| `populateUnusedResources` | +0x8a4 | `void (void *ds, void *objectMap)` |
| `GTMTLReplayController_makeController` | +0x954 | `void* (void *ds, void *pool, void *device, void *objectMap, NULL, NULL)` |
| `GTMTLReplayController_optimizeRestores` | +0x96c | `void (void *controller)` |

导出函数（直接 dlsym）：

| 函数 | 签名 | 验证状态 |
|------|------|---------|
| `GTMTLReplayController_playAll` | `int (void *controller)` | ✅ R4.2 |
| `GTMTLReplayController_playTo` | `int (void *controller, uint32_t targetCallIndex)` | ✅ R4.3 |
| `GTMTLReplayController_rewind` | `void (void *controller)` | ✅ R4.2 |

### playTo 签名确认（R4.3 反汇编证据）
- `+0x020: mov x19, x1` — 仅保存 x0 (controller) 和 x1 (target)，确认 2 参数
- `+0x114: cmp w8, w19` — x1 作为 32-bit 整数用于比较（draw call 索引）
- 返回 0 = 成功；`rewind` 后可重复执行

## 3. GTMTLReplayObjectMap

302 方法的 NSObject 子类，replay 期间所有 GPU 对象的注册表：
- MTLDevice, MTLCommandQueue, MTLBuffer, MTLTexture
- Pipeline states, Libraries, Functions
- Encoders, Command Buffers
- `resources` → NSDictionary（全部资源）
- `bufferForKey:` / `textureForKey:` — 直接数据访问
- `defaultCommandQueue` — 有效 MTLCommandQueue

验证确认：playAll 后 `objectMap.resources` 为有效 NSDictionary，`objectMap.defaultCommandQueue` 为有效 MTLCommandQueue。

## 4. Controller 路径 vs CLI 路径

| 维度 | CLI 路径 (R3) | Controller 路径 (R4.2) |
|------|-------------|----------------------|
| 入口函数 | `GTMTLReplay_CLI` | `makeDataSource` + `makeController` |
| 能力 | 仅 replay 验证（返回 0/非 0） | 完整 replay + 对象访问 + playTo |
| 数据获取 | ❌ | ✅ 通过 objectMap |
| XPC/Entitlement | ❌ 不需要 | ❌ 不需要 |

---

## 5. GTMTLReplayController_init vs makeController

- `GTMTLReplayController_init`：XPC Service 全局初始化（设置 transport + 全局状态），CLI 从不调用
- `GTMTLReplayController_makeController`：实际创建 controller 对象（接受 dataSource+pool+device+objectMap），CLI 内部使用

---

## 6. 已验证的数据获取能力（R4.3）

| 操作 | 方法 | 状态 |
|------|------|------|
| 资源枚举 | `objectMap.resources` → NSDictionary (key=NSNumber ID, value=MTLTexture/MTLBuffer) | ✅ |
| Texture 导出 | `[tex getBytes:bytesPerRow:fromRegion:mipmapLevel:]` | ✅ RGBA8 512×512 = 1MB |
| Buffer 导出 | `[buf contents]` + memcpy | ✅ |
| 定向 replay | `playTo(controller, N)` — resources count 随 N 变化 | ✅ |
| Depth/Stencil 读取 | playAll 后全零 — 可能需在正确 draw call 后读取 | ⚠️ |

**关键观察**：数据获取无需 XPC Fetch 类族，直接从 objectMap 读取，性能优于网络传输。

## 7. GPU Counters 能力边界（R4.4）

| 计数器类型 | 可用性 | 方法 |
|-----------|--------|------|
| Host timing (per-segment) | ✅ | `mach_absolute_time` + playTo |
| GPU timing (独立 cmdBuf) | ✅ | MTLCommandBuffer.GPUStartTime |
| ALU/Cache/Bandwidth | ❌ | 需 GPURawCounter + `com.apple.private.agx.performance-spi` + SIP 关闭 |

Host timing 关键洞察：playTo per-segment timing 显示 GPU workload 集中在 call index 10-20 之间（从 0.015ms 跳变至 2.583ms），对 performance debugging 有价值。
