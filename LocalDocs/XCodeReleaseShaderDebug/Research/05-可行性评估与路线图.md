# 05 - 可行性评估与路线图

## 一、核心难点

Release 包体截帧后，gputrace 中的 shader 数据处于两种状态：

| 层级 | 数据位置 | 格式 | 能否提取 |
|---|---|---|---|
| **Metal IR** | `device-resources` MTSP 容器内 | Pipeline State Binary | ❌ MTSP 格式未公开 |
| **GPU Native Code** | GPU 驱动编译结果（运行时） | AGX ISA | ❌ 未序列化到 gputrace |
| **源码** | gputrace 根目录 hash 文件 | MSL 文本 | ✅ 仅限编译时嵌入的 |

**根本问题**：gputrace 中**既没有**独立的 `.metallib`，**也没有** LLVM Bitcode。Pipeline State 已经是驱动编译后的最终形态，封装在私有的 MTSP 格式中。

## 二、五条路线的可行性评估

### 路线 A：从 gputrace 中提取 metallib 并反汇编

**可行性：🔴 低**

- MTSP 格式未公开，内部不含独立的 MTLB 区块
- Pipeline State 已是编译后的 GPU binary，不是 Metal IR
- 需要先逆向 MTSP 格式，工作量极大

### 路线 B：从 App 安装包中提取 metallib

**可行性：🟢 高**

- Unity 游戏的 `.metallib` 通常位于 `Data/RawData/` 或 App Bundle 内
- 用 MetalLibraryArchive 提取函数列表和 LLVM Bitcode
- 用 `llvm-dis` 反汇编为可读 LLVM IR
- **但**：无法直接关联到 gputrace 中的特定 draw call

操作路径：
```bash
# 1. 找到 app 内的 metallib
find /path/to/app.app -name "*.metallib"

# 2. 用 MetalLibraryArchive 提取
# 3. 用 llvm-dis 反汇编
# 4. 手动根据函数名匹配 draw call
```

### 路线 C：构造伪 metallibdsym 注入到 gputrace

**可行性：🟡 中**

思路：
1. 从 App 包提取 `.metallib`
2. 用 MetalLibraryArchive 提取 LLVM Bitcode
3. 用 `llvm-dis` 生成可读 IR 文本
4. 构造 `.metallibdsym` 目录结构，将 IR 文本作为"源码"
5. 用 DWARF 工具生成行号映射
6. 放入 gputrace 目录中

**难点**：
- 需要构造正确的 UUID 匹配
- DWARF 行号映射需要知道 Metal IR 地址范围
- Xcode 可能验证 metallibdsym 的完整性
- MTSP 中的 pipeline 引用方式不明

### 路线 D：利用 "Import Sources" 按钮

**可行性：🟡 中**

- Xcode 弹出的对话框提供 "Import Sources" 按钮
- 允许用户手动指定 `.metal` 源码目录
- 但需要**函数名完全匹配** — 从 gputrace 中提取函数名，反汇编后生成同名的 `.metal` 文件

**问题**：
- 不确定 Xcode 是否只按函数名匹配，还是也校验编译 hash
- 如果校验 hash，即使提供正确函数名的文件也会被拒绝
- 需要实验验证

### 路线 E：运行时拦截，在截帧前注入调试信息

**可行性：🟢 高（PlayCover 最适合的方案）**

思路：在 PlayCover/PlayTools 中：
1. Hook `MTLDevice.newLibrary(data:)` / `makeLibrary(source:)` 等
2. 拦截 app 加载的每个 `.metallib`
3. 用 MetalLibraryArchive 提取 Bitcode，用 `llvm-dis` 反汇编
4. 将反汇编结果作为"伪源码"，用 `metal -frecord-sources` 重新编译
5. 或直接修改 metallib 的 Embedded Source section
6. 替换原始 metallib 后返回给 app
7. 后续截帧时 Xcode 就能看到"源码"（实际是反汇编结果）

**优点**：
- 在正确的时机拦截，可以处理所有 metallib
- 生成的调试信息与 pipeline 天然匹配
- 可以在 PlayCover settings 中开关此功能

**难点**：
- 需要在设备上运行 `llvm-dis`（或嵌入简化版 IR 打印器）
- 重编译可能改变优化结果，导致 IR 地址不匹配
- 性能开销（每次启动都要处理所有 metallib）
- 某些 app 可能在运行时动态生成 metallib

## 三、推荐路线

### 短期（立即可做）：路线 B

从 App 包中提取 metallib → 反汇编 → 手动分析。
不改代码，纯工具链操作。

### 中期（PlayCover 增强）：路线 E

在 PlayTools 中 hook metallib 加载，注入 `-frecord-sources` 重编译后的 library。
这是最"正确"的方案，但工程量较大。

### 探索性（需实验）：路线 D

测试 "Import Sources" 按钮是否接受函数名匹配的源码。
如果可行，是最轻量的方案。
