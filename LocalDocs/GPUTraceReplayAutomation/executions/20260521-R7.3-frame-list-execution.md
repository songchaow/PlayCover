## 2. 设计决策

### 2.1 swizzle-first vs reflect controller.commandBuffers

`subdocs/20260521-R7-frame-inspection-gap.md §5.3 "为什么是 swizzle-first"` 给出过完整论证。本次执行直接采用 swizzle-first，原因：

- 公开 Metal API 在 macOS 大版本之间稳定性远高于 GPUToolsReplay 的内部布局。
- R7.2 的 `rps_install_swizzles` 已经验证过"装在 `replay_context_init` 之前"模式可靠 — 直接复用，没有"反射 + fallback to swizzle" 的双码路。
- 一次冲刺同时附带 R7.6 子项 C 段 1（draw→RPS_key），把后者从独立 chunk 退化为薄封装。

### 2.2 swizzle 安装时机

| 类 | 时机 | 实现 |
|----|------|------|
| `MTLCommandQueue` 实现类 | 与 RPS swizzle 同时机（`replay_context_init` 之前） | `frame_install_swizzles()` 调 `MTLCreateSystemDefaultDevice → newCommandQueue → object_getClass` |
| `MTLCommandBuffer` 实现类 | 同上 | 同函数中通过 throwaway `[queue commandBuffer]` 取 class（capture gate 关，throwaway CB 被忽略） |
| `MTLRenderCommandEncoder` 实现类 | **延迟到第一次 `renderCommandEncoderWithDescriptor:` 调用** | swizzle thunk 内幂等检查 + `frame_install_render_encoder_swizzles(object_getClass(encoder))` |

延迟安装 render encoder 的原因：在 init 时不容易拿到 concrete encoder 类（需要先走完 cb 创建），通过在 `swz_cb_render` 内首次成功创建 encoder 时立即捕获其类，零开销且自然。

### 2.3 capture gate

`g_frame_capture_armed` 是一个 `volatile sig_atomic_t`：

- `frame_install_swizzles` 期间是关的 — throwaway queue+cb 被 swizzle 但落表函数早退。
- `cmd_frame_list` 在 `safe_playAll` 之前置 1，之后置 0。
- 结果：`g_cb_captured / g_encoder_captured / g_draws_captured` 只反映 trace 真实回放期间发生的事，不会被 framework 在 `makeController` 阶段创建的辅助对象污染。

### 2.4 draw → rps_key 的两步映射

每次 `drawXXX:` swizzle thunk 落表的是 `current_rps_ptr`（也就是 Metal 返回给应用的 RPS 实例指针）。最终 JSON 里的 `rps_key` 通过：

1. `[objectMap renderPipelineStateForKey:k]` 在 `[0..rpsScan]` 内做一遍探测，建 `rps_ptr → rps_key` 字典（与 `pipeline` 子命令同样的 scan 逻辑，含 `funcMap_max + 200` 的 RPS-specific headroom）。
2. 输出阶段对每个 draw 的 `rps_ptr` 字典查询。

LYSK 实测：244 个 draw 全部命中字典；65 个 unique RPS 指针对应 65 个 RPS key。

### 2.5 Render pass attachment 快照

每个 render encoder 在 `renderCommandEncoderWithDescriptor:` swizzle thunk 内立即 snapshot RenderPassDescriptor：

- `colorAttachments[0..7]` 的 `texture / pixelFormat`
- `depthAttachment.texture / pixelFormat`
- `stencilAttachment.texture / pixelFormat`
- `texture` 通过 `frame_lookup_resource_id` 反查 `objectMap.resources` 字典，得到 trace-internal resource id（与 `replay --list-resources` 输出对齐）

线性扫资源字典在 LYSK 上每 encoder 几百次 ID 比较 — encoder 总数 62，整体可忽略。

## 5. 已知限制与后续 TODO

1. **per-encoder GPU timing 经常返回 null**：`MTLCommandBuffer.GPUStartTime/EndTime` 在很多 replay 内部 cb 上保持 0。已在 SKILL.md / cli-reference.md / 本文档显式说明，引导用户回退到 `replay --playto N` 二分。flag 保留，未来若有需要可补"基于 `addCompletedHandler:` 的回调路径"。
2. **compute encoder dispatch 数恒为 0**：`MTLComputeCommandEncoder.setComputePipelineState:` / `dispatchThreadgroups:*` 暂未 swizzle。R7.5 子项 B 顺手补齐；当前 frame-list 仍把 compute encoder 列出来（type=compute, draw_count=0），不影响整体 timeline。
3. **indirect draw 未覆盖**：`drawPrimitives:indirectBuffer:*` / `drawIndexedPrimitives:*indirectBuffer:*` 两个间接 draw 变体没 swizzle。LYSK trace 没用到；如未来某 trace 大量使用，把它们加进 `frame_install_render_encoder_swizzles` 即可（结构化数据上 `vertex_count/instance_count` 设为 0 + 加 `indirect: true`）。
4. **binding 表（`setVertexBuffer:` / `setFragmentTexture:` / `setVertexBytes:`）**：按设计推迟，是 R7.6 子项 A 的范围。
5. **shader-of-drawcall 薄封装**：R7.3 已让其退化成 `lookup draw_to_rps_map[N].rps_key → call shader-of-rps(rps_key)`。建议 R7.6 子项 C 单独 0.5 天 PR，或直接由 wrapper 端实现（无需新 bridge 子命令）。
