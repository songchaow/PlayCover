## PlayCover MCP 接入与验证

### 一、GUI 接入（推荐）

当前推荐接入方式是 **PlayCover GUI 内嵌 HTTP MCP**。

#### 1. 默认端点

```text
http://127.0.0.1:19820/mcp
```

#### 2. 在哪里看当前端点

GUI 中的 `Settings` → `MCP` 页面会显示：

- 当前 transport
- 可复制 endpoint
- 实际监听地址
- 当前连接 / session 数

对应文件：`PlayCover/Views/Settings/MCPStatusView.swift`

#### 3. transport 选择建议

- **优先 HTTP**
- 仅在兼容场景或旧系统上使用 TCP
- 不要把 `0.0.0.0` 当作客户端复制用 endpoint；对客户端应继续使用 `127.0.0.1`

### 二、CLI 接入

CLI 模式仍然保留，入口为 `PlayCoverMCP`。

适用场景：

- 本地 stdio MCP 客户端
- 不依赖 GUI 的最小测试环境
- 回归验证 CLI 未被 GUI HTTP 方案破坏

### 三、最小 HTTP 冒烟流程

#### 1. initialize

```bash
curl -X POST http://127.0.0.1:19820/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"test","version":"1.0"}}}'
```

成功后应拿到：

- JSON-RPC 响应 body
- `Mcp-Session-Id` header
- `Mcp-Protocol-Version` header

#### 2. initialized notification

```bash
curl -X POST http://127.0.0.1:19820/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Mcp-Session-Id: <session-id>" \
  -H "Mcp-Protocol-Version: 2025-11-25" \
  -d '{"jsonrpc":"2.0","method":"notifications/initialized"}'
```

#### 3. tools/list

```bash
curl -X POST http://127.0.0.1:19820/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Mcp-Session-Id: <session-id>" \
  -H "Mcp-Protocol-Version: 2025-11-25" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'
```

#### 4. 打开 SSE 监听流

```bash
curl -N http://127.0.0.1:19820/mcp \
  -H "Accept: text/event-stream" \
  -H "Mcp-Session-Id: <session-id>" \
  -H "Mcp-Protocol-Version: 2025-11-25"
```

#### 5. 关闭 session

```bash
curl -X DELETE http://127.0.0.1:19820/mcp \
  -H "Mcp-Session-Id: <session-id>"
```

当前建议统一使用 ad-hoc 签名参数构建：

```bash

  -derivedDataPath /tmp/PlayCover-DerivedData \
```

### 六、GUI live 验证注意事项

#### 1. 优先验证你命中的就是目标 `.app`

不要默认用：

- `open -a PlayCover`
- 直接执行 `Contents/MacOS/PlayCover`

更稳妥的做法是：

- 先通过安装流程把 `.app` 放到 Applications
- 再用**绝对路径**打开目标 app

#### 2. GUI 重启后要重新 initialize

只要 GUI 重装、重启、切换 transport，原有 `Mcp-Session-Id` 都不应继续复用。

### 七、Session / Runtime 联调前检查

如果你要测 `create_session`、`tap`、`swipe`、`press_key`、`capture_metal_frame`，建议先检查：

1. GUI HTTP 端点是否正常
2. `52741` 是否被当前 `PlayCover.app` 持有
3. 是否有残留 CLI `PlayCoverMCP` 进程占用 runtime 注册端口
4. 被测 app 是否 fresh launch

### 八、验证分层建议

#### L1：构建验证

- `PlayCover` GUI scheme build
- `PlayCoverMCP` CLI scheme build

#### L2：单元测试

- `PlayCoverMCP` 全量 tests

#### L3：协议级冒烟

- `initialize`
- `tools/list`
- `resources/list`
- SSE primer event
- `DELETE /mcp`

#### L4：能力级验证

- 只读工具
- 设置修改
- keymap 增删改查
- `install_ipa` 与任务查询

#### L5：真实 runtime 联调

- `create_session`
- `tap` / `swipe` / `drag`
- `press_key` / `type_text`
- `capture_metal_frame`

### 九、接入结论

如果你今天要新写一个 PlayCover MCP 客户端，最稳妥的默认假设应该是：

1. **GUI 用 HTTP**
2. **CLI 用 stdio**
3. **需要流式通知时一定建立 SSE**
4. **长任务不要只看 `install_ipa` 的返回值，要继续用 `get_task` / `list_tasks`**
5. **GUI restart 之后重新 initialize，拿新 session**
