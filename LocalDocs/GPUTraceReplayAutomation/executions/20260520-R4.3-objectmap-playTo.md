5. **Depth/Stencil 格式**（如 fmt=252 Depth32Float_Stencil8）在 playAll 后读出全零——可能需要特殊 getBytes 调用或在正确的 draw call 后读取
6. **RGBA 格式 texture**（如 fmt=70 RGBA8Unorm）数据完整非零，验证了 pixel data 导出的正确性

## Phase B：playTo 定向 Replay

### 签名确认

通过动态加载 + ARM64 反汇编确认：

```c
int GTMTLReplayController_playTo(void *controller, uint32_t targetCallIndex);
```

**反汇编证据**：
- `+0x020: mov x19, x1` — 仅保存 x0 (controller) 和 x1 (target)，确认 2 参数
- `+0x114: cmp w8, w19` — x1 作为 32-bit 整数用于比较（draw call 索引）
- `playTo` 是导出函数（地址 0x001BAC90），可直接 `dlsym` 调用

### 验证结果

| 调用 | 返回值 | resources count | 结论 |
|------|--------|----------------|------|
| `playTo(controller, 1)` | 0 | 258 | ✅ 定向 replay 到第 1 个 call |
| `playTo(controller, 10)` | 0 | 259 | ✅ 定向 replay 到第 10 个 call |
| `playAll(controller)` | 0 | 262 | 基准（全部 replay） |

**关键观察**：
- `playTo` 返回 0 = 成功（与 `playAll` 语义一致）
- resources count 随 playTo 目标变化（258 → 259 → 262），证明定向 replay 正确停在不同位置
- `rewind` 后再 `playTo` 可重复执行，状态可重置

### Texture 内容对比

对 `DirectionalShadowDepth` 对比 playTo(1) vs playTo(10)：结果相同。  
原因：Shadow depth 是 early pass 产物，在 draw call 1-10 范围内未被写入。  
**后续可对比 render target（如 LastFrameTexture0）以验证 draw call 级别的渲染差异。**
