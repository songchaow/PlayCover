### 文档目的

这里是 `PlayCover MCP` 的**实施指挥目录**。后续每个 agent 都应从这里进入，再按固定顺序阅读前置文档与单个任务卡。

### 目录结构

- **`00-README-导航.md`**：导航与阅读顺序
- **`01-总体规划与架构.md`**：目标范围、总体架构、能力边界
- **`02-Agent-执行入口.md`**：agent 开工前 / 收工前固定动作
- **`03-共享前置信息.md`**：仓库、工程、构建、现状事实
- **`04-测试与验证策略.md`**：每个任务必须遵守的测试策略
- **`05-提交与文档更新规范.md`**：每个任务必须遵守的提交与文档更新规则
- **`06-全局任务看板.md`**：全部任务总览与状态
- **`07-任务依赖与推荐执行顺序.md`**：推荐执行路径与依赖关系
- **`Templates/任务卡模板.md`**：后续新增任务时参考模板
- **`Tasks/`**：单次执行任务卡目录

### agent 的固定阅读顺序

每次只做一个任务。开工前必须按这个顺序阅读：

1. `00-README-导航.md`
2. `01-总体规划与架构.md`
3. `02-Agent-执行入口.md`
4. `03-共享前置信息.md`
5. `04-测试与验证策略.md`
6. `05-提交与文档更新规范.md`
7. `06-全局任务看板.md`
8. 本次要执行的 `Tasks/*.md`

### 执行原则

- **一次只做一个任务卡**
- **不要顺手扩 scope**
- **每个任务结束都要做测试**
- **每个任务结束都要更新文档**
- **每个任务结束都要 `git commit`**

### 当前范围

本轮规划覆盖：

- **Host 侧 MCP 功能**
- **Session 侧 MCP 功能**
- **测试与验证体系**
- **任务化执行与文档化协作机制**

本轮**明确排除**：

- **运行中 attach debugger**
- IPA 资源库 / Store 类附属能力

### 如何选任务

先看 `06-全局任务看板.md`，再看 `07-任务依赖与推荐执行顺序.md`。

- 如果是第一批 agent，从 `H00` 开始
- 如果上游任务已完成，按依赖选择下一个未完成任务
- 如果任务被标记为 `BLOCKED`，先不要硬做，先处理依赖项
