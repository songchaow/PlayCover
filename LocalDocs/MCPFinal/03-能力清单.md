## PlayCover MCP 能力清单

### 一、能力组织方式

当前 PlayCover MCP 的能力可以按四层理解：

1. **Tools**：动作型接口
2. **Resources**：状态快照接口
3. **Logging**：日志级别设置与日志通知
4. **Tasks**：长任务状态查询与取消

此外，Session / Touch / Input / Capture 属于 tools/resources 之上的业务域。

### 二、Tools 总表

当前代码实际注册了 **47 个 tools**。

#### A. 应用信息

| Tool | 说明 |
|---|---|
| `list_installed_apps` | 列出 PlayCover 管理的已安装应用 |
| `get_app_info` | 获取单个已安装应用的详情 |

#### B. 安装与导出

| Tool | 说明 |
|---|---|
| `install_ipa` | 安装 IPA；长任务。支持三种文件来源（见下方） |
| `export_patched_ipa` | 导出已注入 PlayTools 的 IPA；长任务。支持三种文件来源 |

`install_ipa` 和 `export_patched_ipa` 的 IPA 来源支持三种方式：

| 参数 | 说明 | GUI HTTP | CLI stdio |
|---|---|---|---|
| `ipaPath`（本地路径） | 绝对路径，如 `/Users/.../game.ipa` | ✅ | ✅ |
| `ipaPath`（`@filename` 引用） | 引用通过 `POST /upload` 上传的文件，如 `@a1b2c3d4-game.ipa` | ✅ | ❌ |
| `ipaURL` | HTTP/HTTPS URL，服务端自动下载后安装/导出 | ✅ | ✅ |

参数互斥规则：
- `ipaPath` 和 `ipaURL` 必须提供其中一个
- 若同时提供，优先使用 `ipaURL`
- 使用 `ipaURL` 时，进度分为两阶段：0-40%（下载）+ 40-100%（安装/导出）

### 四、Logging 能力

#### 1. 已支持内容

当前 server capabilities 开启了 `logging`，并支持：

- `logging/setLevel`
- `notifications/message`

#### 2. 日志级别

当前支持的 `LogLevel`：

- `debug`
- `info`
- `notice`
- `warning`
- `error`
- `critical`

#### 3. 推送方式

日志本身通过 `MCPLogger` 产生，并在 `MCPServer.wireNotifications()` 中接入到 HTTP SSE 推送。

### 五、Tasks 能力

#### 1. JSON-RPC method

当前 `MCPServer` 注册了以下 task method：

- `tasks/create`
- `tasks/get`
- `tasks/list`
- `tasks/cancel`

#### 2. Tool 等价物

同时也通过标准 tool 路径对外暴露：

- `get_task`
- `list_tasks`
- `cancel_task`

#### 3. 状态模型

当前 `TaskState` 包含：

- `pending`
- `running`
- `completed`
- `failed`
- `cancelled`

#### 4. SSE 任务通知

任务状态变更会通过：

- `notifications/tasks/status`

向客户端推送。

### 六、Session / Touch / Input / Capture 的实际边界

#### 1. Session 前提

要使用触控、输入、截帧，前提不是只有 HTTP MCP 可用，还包括：

- Host 侧 `RegistrationListener` 已启动
- runtime 侧已向 host 注册
- `create_session` 成功

#### 2. Runtime 注册端口

runtime 注册监听使用的默认端口为：

- **`52741`**

#### 3. Capture 特殊前提

`capture_metal_frame` 的使用前提更严格：

- 对应 app 的 `metalCaptureEnabled` 必须开启
- 修改该设置后需要**重新安装**应用
- runtime 侧需要具备 PlayTools capture 能力

### 六点五、文件传输能力

#### 1. POST /upload（HTTP transport 专属）

`POST /upload` 是一个辅助 HTTP 端点，不属于 MCP JSON-RPC 协议，但与 `/mcp` 并列。

用途：Agent 位于远端时，先将文件上传到 PlayCover MCP，再通过 `@filename` 引用在 tool 参数中使用。

详细协议行为见 `02-HTTP传输与协议.md` 的 `五点五` 节。

#### 2. ipaURL（tool 内置下载）

`install_ipa` 和 `export_patched_ipa` 直接接受 `ipaURL` 参数（HTTP/HTTPS），服务端自动下载后执行。

此能力 HTTP 和 CLI 均可用，不依赖 `/upload` 端点。

#### 3. 设计定位

| 方式 | 定位 | transport 限制 |
|---|---|---|
| `POST /upload` + `@引用` | 通用文件暂存，适用于任何需要本地文件的 tool | 仅 HTTP |
| `ipaURL` | IPA 专项快捷路径，一次调用完成下载+安装 | HTTP + CLI |

两者互补。对于跨机器装包，推荐优先使用 `ipaURL`（更简单）。当需要复用同一上传文件做多次操作时，使用 `/upload`。

### 七、当前不支持 / 不作为主能力的内容

#### 1. Prompts

当前 server capabilities **没有开启 `prompts`**。

#### 2. 旧 raw TCP GUI SOP

虽然 `TCPTransport` 仍存在，但不再作为当前 GUI 文档的默认能力路径。

#### 3. UI tree / selector 级自动化

当前实现重点仍是：

- host 管理
- runtime session
- touch / key / text / overlay
- capture

而不是基于可访问性树的高级 UI 语义自动化。

### 九、结论

如果只记住一句话，那就是：

> **PlayCover 当前的 MCP 已经不是"只会列应用"的轻量工具，而是一套同时覆盖 Host 管理、跨机器文件传输与 URL 装包、长任务、runtime session、输入自动化和 Metal 截帧的完整本地控制面。**
