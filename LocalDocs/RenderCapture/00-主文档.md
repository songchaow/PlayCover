## Metal 截帧功能（RenderCapture）

### 目标

为 PlayCover 添加对运行中 iOS app 的 **Metal GPU 截帧**能力，允许用户触发一次截帧操作，将 `.gputrace` 文件导出到指定路径，随后可用 Xcode 打开进行渲染流程分析。

### 技术路线

**路径1：Info.plist + MTLCaptureManager API 编程式截帧**

在 app 的 Info.plist 中声明 `MetalCaptureEnabled = YES`，然后在 PlayTools dylib 运行时中通过 `MTLCaptureManager.shared()` 的 API 进行编程式截帧，将 `.gputrace` 文件写入磁盘。

### 关键技术要点

#### 1. Info.plist `MetalCaptureEnabled`

- macOS 上的 Catalyst 应用如果要使用 `MTLCaptureManager` 的编程式截帧，**必须**在 Info.plist 中设置 `MetalCaptureEnabled = YES`
- 这个 key 在安装时写入（Installer.swift），类似现有的 `MinimumOSVersion` 修改
- **注意**：此 key 仅在 app 启动时读取，修改后需要重新安装或重签名才能生效

#### 2. 环境变量清除机制

- `PlayApp.swift` 的 `clearDebugAffectingEnvironment()` 和 `runAppExec()` 会在启动前清除 13 个 Metal 相关环境变量
- 包括 `METAL_CAPTURE_ENABLED`、`METAL_CAPTURE_OUTPUT_FILE` 等
- **对于编程式截帧（使用 MTLCaptureManager API），Info.plist 的 `MetalCaptureEnabled` 足够，不需要环境变量**
- 因此环境变量清除机制**不需要修改**——编程式截帧不依赖环境变量

#### 3. PlayTools 侧截帧实现

- PlayTools 运行在目标 app 进程内（作为注入的 dylib），能够直接访问 Metal API
- `MTLCaptureManager.shared()` 可以获取截帧管理器
- `supportsDestination(.gpuTraceDocument)` 检查是否支持导出 `.gputrace`
- `MTLCaptureDescriptor` 设置截帧范围（captureObject 传 device 或 commandQueue）和输出 URL
- `startCapture(with:)` 开始截帧，`stopCapture()` 结束截帧
- 截帧覆盖一帧的 GPU 命令提交

#### 4. 设置共享机制

- PlayCover Host 和 PlayTools 通过共享 plist 文件通信：
  `~/Library/Containers/io.playcover.PlayCover/App Settings/{bundleId}.plist`
- 新增 `metalCaptureEnabled` 字段到 `AppSettingsData`
- PlayTools 侧的 `AppSettingsData` 需要同步新增该字段

#### 5. 沙箱与文件访问

- 目标 app 运行在 app-sandbox 下
- `.gputrace` 输出路径需要在沙箱可写范围内
- 推荐输出到 app 的 container 目录或 `~/Library/Containers/io.playcover.PlayCover/` 下

### 统一测试策略

#### 核心原则

1. **测试是累积的**：每个 task 完成后，必须通过**本 task 新增的所有测试** + **之前所有 task 已有的测试**
2. **统一验证脚本**：所有自动化验证项统一收敛到 `Scripts/verify_render_capture.sh`，每个 task 往脚本中追加新的检查项，不删除已有的
3. **完成一个 task 就跑全量**：agent 收工前执行 `./Scripts/verify_render_capture.sh`，脚本会运行所有已激活的检查项（未实现的 task 对应的检查会被自动跳过）
4. **人工验证单独记录**：无法自动化的验证项在脚本中以注释形式标注，并在对应 task 文档中给出手动步骤

### 注意事项

1. **PlayTools 是 Carthage 依赖**：`Carthage/Checkouts/PlayTools/` 目录下的修改需要谨慎，它是通过 Carthage 管理的。修改 PlayTools 代码后需要确保 framework 能正确编译
2. **pbxproj 修改风险**：如果需要新增文件到 Xcode 项目，参考 `LocalDocs/MCP/08-经验教训与常见陷阱.md` 中的经验教训
3. **PlayCoverMCP 不能导入 PlayCover 模块**：MCP target 是独立的 CLI tool，不链接 PlayCover framework
4. **两份 AppSettingsData**：PlayCover Host 侧和 PlayTools 侧各有一份 `AppSettingsData` 定义，新增字段时两边都要同步
5. **沙箱限制**：目标 app 运行在沙箱中，文件 I/O 路径需要在沙箱允许范围内
6. **编程式截帧不需要环境变量**：`MTLCaptureManager` API 只需要 Info.plist 的 `MetalCaptureEnabled = YES`，不依赖 `METAL_CAPTURE_ENABLED` 等环境变量，因此**不需要修改** `clearDebugAffectingEnvironment()` 的逻辑
