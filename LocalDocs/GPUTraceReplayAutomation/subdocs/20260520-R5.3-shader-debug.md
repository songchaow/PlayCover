# R5.3 技术参考：Shader Debug 架构与替代方案

**状态**：⚠️ 部分可行 — 原生路径受 GTLLVMHelper IPC 限制；instrumented debug 替代方案完全可行  
**方法**：V1 静态 introspection + V4 动态验证

---

## 1. 核心结论

- ❌ **原生 shader debugger**：需 GTLLVMHelper IPC 连接，最小 client 不满足
- ✅ **Instrumented debug**（printf 风格）：通过 R5.2(替换) + R4.3(playTo+读取) 组合完全可行
- ✅ **无源码 shader 调试**：shaderIR 路径 + 反汇编/修改/重编译工作流可行
- 🎯 对于自动化场景，instrumented debug 比交互式 debug 更适合

---

## 2. ShaderDebug 请求类族

```
GTReplayShaderDebugRequest (super: GTReplayRequest)
├── GTReplayShaderDebugKernel       — compute (min/maxThreadPositionInGrid)
├── GTReplayShaderDebugFragment     — fragment (min/maxPixelPosition, sampleID)
├── GTReplayShaderDebugVertex       — vertex (vertexIDs, instanceID)
├── GTReplayShaderDebugMesh         — mesh shader
├── GTReplayShaderDebugObject       — object shader
└── GTReplayShaderDebugPostTessellationVertex
```

公共属性：`dispatchUID`、`programData`(NSData)、`programDataVersion`(int)、`completionHandler`(@?)

## 4. 替代方案：Instrumented Shader Debugging

### 工作流

```
原始 shader → 提取 metallib (R5.1: libraryForKey → libraryDataContents)
            → 反编译 (xcrun metal-objdump -disassemble / llvm-dis)
            → 修改 IR（注入 debug store 指令）
            → 重编译 (xcrun metal-lld + xcrun metallib)
            → 注入 (newLibraryWithData + setLibrary:forKey:)
            → rewind + playAll → 读取 debug buffer
```

### 能力对照

| Xcode Shader Debug | 替代方案 | 状态 |
|-------------------|---------|------|
| 选中像素/线程 | playTo + 指定 buffer index | ✅ |
| 查看变量值 | 注入 `out[gid] = variable` | ✅ |
| 单步执行 | 多位置注入，多次 replay 对比 | ✅ (多 pass) |
| 执行轨迹 | 注入 counter 记录路径 | ✅ |
| 无源码支持 | shaderIR — 操作 metallib binary | ✅ |
| 实时交互 | 需多次 replay | ⚠️ 非实时 |

## 5. GTLLVMHelper IPC 探索结论（R5.3b）

### 已验证

| 发现 | 详情 |
|------|------|
| 连接 | Unix socket `/tmp/unixsocketipc_gtd`, connect ✅ |
| 消息格式 | `[uint32 clientIdx][uint32 cmd][uint32 dataLen][data...]` |
| 响应 | 固定 16 bytes ACK：`[uint64 0x3a][echo prefix]` |
| 私有启动 | `GTLLVMHelper g16s Host 0 <pid> 0 <socket_path>` ✅ |

### 阻塞原因

`0x3a` 是通用 ACK — 服务器确认收到但未执行。原因：
1. GTLLVMHelper 使用 **flatbuffers** 序列化格式
2. 可能缺少初始化握手/版本协商
3. 实际命令编码在 flatbuffers payload 内部

### 后续增强方向评估

| 方向 | 可行性 | 工作量 | 价值 |
|------|--------|--------|------|
| 逆向 flatbuffers schema | 中等（binary 有符号残留） | 高（2-4 天） | 完整交互式 debug |
| 拦截 Xcode 实际消息（MITM socket） | 高 | 中（1 天） | 协议学习 |
| GTIRDebugInfo + instrumented | 高（工具已就绪） | 低（已验证） | 有效替代 |

**结论**：IPC 连接层打通，协议层需 flatbuffers 逆向。当前 instrumented debug 已满足需求，IPC 全协议逆向作为**未来增强方向保留，不阻塞主线**。

## 6. GTMTLReplayService 内部结构

```objc
@interface GTMTLReplayService {
    void *_clientContext;              // +8, GTMTLReplayClient*
    NSURL *_gputrace;                  // +16
    xpc_object_t _terminatePath;       // +24
    xpc_object_t _terminateConnection; // +32
    GTObservableService *_observers;   // +40
    uint64_t _servicePort;             // +48
}
```

GTMTLReplayClient 核心结构：pool(+0) + controller(+8) + counter(+16) + capabilities(+24) + config(+64) + observer(~+88) + GTMTLReplayOperationQueues(3 dispatch queue) + extras
