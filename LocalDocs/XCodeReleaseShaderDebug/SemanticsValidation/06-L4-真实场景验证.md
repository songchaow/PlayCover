## L4：真实场景验证

## 文档职责

本文只记录 L4 的**启用条件、工具、验证顺序、用户确认规则与产物建议**。

**任务状态、进展、优先级、TODO、完成判定与是否进入 L4，统一只在 `00-Dashboard.md` 维护。** 本页不重复动态控制面信息。

## 目标

在 L1/L2/L3 已提供较充分离线证据后，用真实 shader、真实 `.gputrace`、真实 app 场景做**最终后置验证**。

L4 主要回答：

- 何时值得进入 live 验证
- replacement / `.gputrace` / render 结构是否真正命中
- 某些问题是否只能在真实 runtime 中暴露

## 启用条件

只有在下面任一情况成立时，才适合进入 L4：

1. 低层证据已经足够多，但仍需要真实确认
2. 某类问题只能在 runtime / `.gputrace` / render 结构中暴露
3. 改动直接影响 runtime replacement 主链路
4. 用户明确要求进入 live 验证

如果问题仍能在离线层被更低成本地解释，就不应过早扩大到 L4。

## 默认工具

优先使用已存在的自动化工具：

- `Scripts/check_gputrace_sources.py`
- `Scripts/compare_capture_runs.py`
- `Scripts/e006d_render_diff.py`
- `Scripts/runtime_launch_diagnostics_summary.py`
- PlayCover MCP 能力（如 `launch_app`、`create_session`、`capture_metal_frame`、输入事件等）
- `./BuildScripts/build_and_install.sh`

约束：

- 构建、安装与重建仍应优先走 `BuildScripts/` 标准脚本
- 不要手写 `xcodebuild` 代替标准脚本
- 若未来新增 L4 方法，也应优先保证它仍能以脚本 / MCP 方式自动执行

## 默认验证顺序

### 第一步：先看源码与 replacement 闭环

优先确认：

- replacement 是否稳定命中
- `.gputrace` 是否能看到对应源码
- run 间输入与 replacement attempt 是否稳定

### 第二步：再看渲染结构

若源码可见、replacement 已命中，但仍怀疑行为差异，则再比较：

- Command Buffer 数量
- Render Encoder 结构
- Pipeline State 摘要
- 关键 pass 差异

相关工具通常包括：

- `compare_capture_runs.py`
- `e006d_render_diff.py`

### 第三步：必要时再做更重的 live / GUI 分析

只有当自动化结构证据仍不够时，才考虑：

- 更细粒度的 key pass details
- 更长链路的 live 对照
- 需要 GUI / Accessibility 的专项分析

## 用户确认规则

以下情况必须先得到用户确认：

- 需要人工登录 / 摆场景 / 点击 UI
- 需要 GUI / Accessibility / `cliclick`
- 需要修改工作区外文件或 app bundle
- 需要长时间占用机器做大规模 live 对照
- 需要超出默认自动化边界的外部协助

执行前至少应说明：

- 需要用户做什么
- 为什么必须做
- 是否还能进一步缩小步骤

## 不应成为默认 gate 的内容

- 人工打开 Xcode 肉眼确认
- 依赖登录后的复杂场景摆放
- 需要用户反复点按钮
- 无脚本化的长链路 GUI 分析
- 因缺少 live 条件就要求用户补环境

这些路径只能作为专项升级流程，不能回流为日常默认 gate。

## 代表集与产物建议

L4 不应追求样本越多越好，而应维护一组小而稳定的代表集。

建议按两类组织：

- A 类：源码可见性 / replacement 闭环代表集
- B 类：渲染结构 / 行为敏感代表集

建议目录：

```text
build/semantics-validation/real-scene/<timestamp>/
  live-summary.json
  gputrace-summary.json
  render-diff-summary.json
  diagnostics-summary.json
```

## 与其它层的关系

- L4 依赖 L1/L2/L3 提供的前置证据
- L4 用于补充确认，不用于跳过低层
- 是否进入 L4、在什么时机进入，统一由 `00-Dashboard.md` 决定
