## PlayCover MCP 最终文档导航

### 文档目的

本目录用于描述 **PlayCover 当前仍然有效的 MCP 最终形态**。

这里不再按历史阶段记录 stdio MCP、GUI TCP MCP、HTTP MCP 的实施过程，而是直接以**当前代码中的最终结果**为准，回答三个问题：

1. **现在 PlayCover MCP 到底包含什么能力**
2. **当前推荐和受支持的设计是什么**
3. **HTTP MCP 在 GUI 中如何工作，客户端应该如何接入**

### 当前结论

#### 1. 官方形态

- **GUI 内嵌 MCP**：以 **Streamable HTTP** 为主形态
- **CLI MCP**：继续保留 **stdio** 形态
- **TCP MCP**：代码保留，但只作为 **兼容 / 回退 transport**，不再作为文档主方案

#### 2. 传输层定位

| 传输层 | 当前角色 | 入口 |
|---|---|---|
| `StreamableHTTPTransport` | **GUI 默认方案** | `PlayCover/Services/MCPManager.swift` |
| `StdioTransport` | **CLI 保留方案** | `PlayCoverMCP/main.swift` |
| `TCPTransport` | **兼容 / 回退方案** | `PlayCover/Services/MCPManager.swift` |

### 当前 MCP 能力总览

#### Host 侧

- 应用列表与详情
- IPA 安装与导出（支持本地路径、`@filename` 上传引用、远端 URL 三种方式）
- 文件上传（`POST /upload`，仅 HTTP transport）
- 应用启动 / LLDB 启动
- 卸载与多种清理动作
- 设置读取 / patch 更新 / 重置
- 签名诊断与重签
- PlayTools 注入 / 去注入 / 运行环境切换
- keymap 全生命周期管理
- 长任务状态查询与取消

#### Session 侧

- 运行时 session 创建 / 查询 / 关闭
- 触控：`tap` / `long_press` / `swipe` / `drag`
- 输入：`press_key` / `type_text` / `toggle_debug_overlay`
- Metal 截帧：`capture_metal_frame` / `get_capture_status`

#### 协议侧

- `tools`
- `resources`
- `logging`
- `tasks`
- HTTP SSE 服务端推送

### 关键边界

以下内容**不属于当前文档主范围**：

- 旧 raw TCP 手工 `nc` 初始化流程
- 旧的任务卡式实施过程文档
- 已弃用 transport 的分阶段实施 SOP

如需理解“为什么历史上会有 TCP / stdio / HTTP 三阶段”，只需记住：

1. 先有 **CLI stdio MCP**
2. 再有 **GUI 内嵌 TCP MCP**
3. 最终收敛到 **GUI 内嵌 Streamable HTTP MCP**

但现在对外应以 **HTTP MCP 最终形态** 为准。
