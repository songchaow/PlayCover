## 1. 核心发现

### 1.1 Controller 创建路径（从 CLI 反汇编确认）

CLI 函数内部 **不直接调用** `GTMTLReplayController_init`（该函数是给 XPC service 用的全局初始化）。CLI 使用如下调用链创建 controller：

```
apr_pool_create_ex(&pool, NULL, NULL, NULL)
    ↓
GTMTLReplayController_makeDataSource(path, pool)
    ↓ → dataSource (APR-based state machine context)
GTMTLReplaySupport_init(device)
    ↓
[[GTMTLReplayObjectMap alloc] initWithDevice:device]
    ↓ → objectMap (302 个方法，管理所有 replay GPU 对象)
GTMTLReplayController_initializeArgumentBufferSupport(dataSource, device, objectMap)
    ↓
GTMTLReplayController_populateUnusedResources(dataSource, objectMap)
    ↓
GTMTLReplayController_makeController(dataSource, pool, device, objectMap, NULL, NULL)
    ↓ → controller (完整 replay controller)
GTMTLReplayController_playAll(controller) → 0
GTMTLReplayController_rewind(controller)
```

### 1.3 关键对象：GTMTLReplayObjectMap

`GTMTLReplayObjectMap` 是 replay 期间所有 GPU 对象的注册表（NSObject 子类，302 个方法）。它管理：
- MTLDevice, MTLCommandQueue, MTLBuffer, MTLTexture
- Pipeline states, Libraries, Functions
- Encoders, Command Buffers
- Resources dictionary (NSDictionary)

验证确认：`playAll` 执行后，`objectMap.resources` 为 NSDictionary，`objectMap.defaultCommandQueue` 为有效 MTLCommandQueue。

## 3. GTMTLReplayController_init vs makeController

`GTMTLReplayController_init` 是给 **XPC Service** 用的全局初始化函数：
- 接受一个 "transport" 参数
- 设置全局状态（bool flags、环境变量读取）
- 存储 transport 到全局变量
- CLI 函数从不调用它

`GTMTLReplayController_makeController` 是 **实际创建 controller 对象** 的函数：
- 接受 dataSource + pool + device + objectMap
- 内部调用 DoLoadJob 加载 GPU 资源
- 返回可用的 controller 指针
- CLI 在内部使用这个函数

---

## 4. GTMTLReplayClient_createNewTransport 分析

该函数用于建立 XPC transport 通道：
1. 创建 APR pool
2. 调用 `GTMTLReplayClient_init(context, pool)` 初始化客户端状态
3. `activateWithMessageHandler:andErrorHandler:` 激活消息处理
4. `initWithProtocol:` 建立 XPC protocol
5. `connection` 获取 XPC connection
6. `initWithService:properties:` 创建 service proxy
7. `registerDispatcher:forPort:` 注册消息分发

**结论**：该函数完全面向 XPC/IPC 场景（Xcode → GPUToolsReplayService.xpc）。对于 headless in-process replay，**不需要**此函数。

## 5. 对后续任务的启示

### R4.3: playTo + Fetch
- Controller 已创建，`playTo` 是导出函数，可直接调用
- ObjectMap 的 `resources` 字典包含 replay 后的所有资源
- 可通过 `objectMap.bufferForKey:` / `objectMap.textureForKey:` 直接获取 GPU 数据
- 无需 XPC Fetch 类族 — **直接从 objectMap 读取即可**

### R4.4: GPU Counters
- 需要 GPURawCounter.framework 的 `GRCCopyAllCounterSourceGroup`
- Controller 提供了执行环境，counters 可在 playAll 前/后采集

### R4.5: Shader Profiler
- 需要确认 `GTMTLReplayController_makeController` 的 arg4/arg5 是否控制 profiling
- `GTReplayProfileTimeline.shaderProfiling` 可能需要通过 objectMap 注册
