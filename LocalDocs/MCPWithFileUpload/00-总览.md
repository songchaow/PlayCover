## PlayCover MCP 文件传输能力扩展

### 背景

当前 `install_ipa` 和 `export_patched_ipa` 工具只接受**本机绝对路径**。当 Agent 从远端调用 PlayCover MCP 时，IPA 文件位于 Agent 侧，无法直接传递给 MCP。

MCP 协议本身是 JSON-RPC over HTTP，没有原生的二进制文件传输能力。

### 目标

通过两个方案解决跨机器文件传输问题：

| 方案 | 定位 | 简述 |
|---|---|---|
| **方案 C：文件上传端点** | 通用文件暂存 | 在 HTTP transport 上新增 `/upload` 端点，接受文件上传，存入临时目录，返回文件名 |
| **方案 D：URL 直装** | IPA 专项快捷路径 | `install_ipa` 新增 `ipaURL` 参数，MCP 自行下载后安装 |

### 两个方案的关系

```text
方案 C（通用）                              方案 D（专项）
─────────────                            ─────────────
Agent ──POST /upload──▶ 暂存目录           Agent ──tools/call install_ipa(ipaURL=...)──▶
Agent ──install_ipa(ipaPath="@filename")  MCP 自动下载到临时目录 → 安装
```

- **方案 C 是基础设施**：提供一个通用的文件暂存机制，任何需要本地文件的 tool 都可以通过 `@filename` 引用上传的文件
- **方案 D 是快捷路径**：Agent 只需一次 MCP 调用即可从 URL 装包，不需要先上传

两者互补，不互斥。

### 实施顺序

1. **先实施方案 C**：文件上传端点 + 暂存目录 + `@filename` 解析
2. **再实施方案 D**：`install_ipa` / `export_patched_ipa` 增加 `ipaURL` 参数

方案 D 可以复用方案 C 的暂存目录基础设施。
