## 1. R8.2 交付物：value_health_summary

### 1.1 功能

对 `dump-uniforms` / `shader-of-drawcall --with-uniforms` / `draw-info --with-uniforms` 输出的 decoded 字段树做一次遍历，统计 NaN / inf / denormal 值的数量和字段定位。

### 1.2 输出 schema

```json
"value_health_summary": {
  "nan_count": 1,
  "inf_count": 0,
  "denormal_count": 0,
  "fields_with_nan": ["_FresnelColor"],
  "fields_with_inf": [],
  "fields_with_denormal": []
}
```

### 1.3 检测规则

| 类型 | 检测条件 |
|------|---------|
| NaN | JSON 字符串 `"NaN"` 或 `math.isnan(float)` |
| inf | JSON 字符串 `"inf"/"Infinity"/"-inf"/"-Infinity"` 或 `math.isinf(float)` |
| denormal | `0 < |v| < 6.1e-5`（half 精度阈值 2^-14） |

### 1.4 注入点

- `dump-uniforms` CLI 输出（单 slot）
- `shader-of-drawcall --with-uniforms` CLI 输出（聚合所有 slot，prefix = binding_name）
- `draw-info --with-uniforms` raw（聚合所有 slot）

### 1.5 验证

LYSK draw 69 / slot 5 (UnityPerMaterial)：
- `_FresnelColor.x = NaN` → `nan_count: 1, fields_with_nan: ["_FresnelColor"]` ✓
- §1.4 错误案例结构性消除：agent 不再需要逐字段目测 NaN

## 2. R8.3 交付物：dump-uniforms --by-name

### 2.1 功能

按 IR `arg_name` 直接查值，绕过 `bind_slot` 心算。

```bash
# 旧方式（需先知道 slot 5 = UnityPerMaterial）：
python3 gputrace_replay_wrapper.py dump-uniforms <trace> 69 5

# R8.3 新方式：
python3 gputrace_replay_wrapper.py dump-uniforms <trace> 69 0 --by-name UnityPerMaterial
python3 gputrace_replay_wrapper.py dump-uniforms <trace> 69 0 --by-name UnityPerMaterial --field _NonMetalSpecular
```

### 2.2 解析链路

```
--by-name <NAME>
    ├── target_kind=draw → frame-list → rps_key
    ├── pipeline → rps_key → fragment/vertex library_key
    ├── disasm --with-ir → .ll file
    ├── parse_air_metadata(.ll) → name→slot 映射
    ├── 精确匹配 name.lower() == by_name.lower()
    │   └── 失败 → 子串匹配
    ├── 解析出 bind_slot
    └── 调用标准 dump-uniforms(target, resolved_slot, ...)
```

### 2.3 --field 过滤

当与 `--by-name` 或普通 `dump-uniforms` 配合使用时，从 decoded 树中过滤出匹配字段名的子集（大小写不敏感子串匹配）。

输出额外字段：
- `field_filter`: 原始 --field 值
- `field_match_count`: 匹配到的字段数

### 2.4 验证

```
draw 69, --by-name UnityPerMaterial:
  binding_name: UnityPerMaterial ✓
  bind_slot: 5 ✓ (自动解析)
  buffer_data_size: 336 ✓

draw 69, --by-name UnityPerMaterial --field _NonMetalSpecular:
  field_match_count: 1 ✓
  decoded: {"_NonMetalSpecular": {"offset": 54, "data_type": "half", "value": 0.983398}} ✓
```

## 3. 设计决策

| 决策 | 理由 |
|------|------|
| denormal 使用 half 阈值 (6.1e-5) | LYSK 中 cbuffer 主要是 half 精度；用更宽松的 float32 阈值 (1.175e-38) 几乎不会触发 |
| --by-name 失败时输出 available_names 列表 | 帮助 agent 快速纠错，避免 "name_not_found → 重新跑 pipeline → 重新 grep IR" 循环 |
| --field 用子串匹配 | 字段名可能带前缀/后缀（如 `_MainTex_ST` vs `MainTex`），精确匹配太严格 |
| value_health_summary 只在有异常时输出 | 正常 draw 不增加输出噪声；NaN/inf/denormal > 0 时才显式提示 |
| bridge 零变更 | R8.2/R8.3 纯粹是 wrapper 层对已有数据的后处理 + 新查询路径 |

---

## 4. 已知局限

1. denormal 检测可能在 float32 精度下产生 false positive（有些合法的小数值在 half 看来是 denormal）— 后续可加 `data_type` 判断
2. --by-name 当前只搜索 buffer bindings，不搜索 texture bindings（texture 无结构化 decode）
3. 聚合模式下（shader-of-drawcall / draw-info），denormal 计数可能较多（half 精度 cbuffer 中小值常见）— 后续 R8.2b 可加白名单/阈值调节
