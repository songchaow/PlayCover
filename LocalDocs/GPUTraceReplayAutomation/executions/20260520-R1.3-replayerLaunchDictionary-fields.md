## 1. 核心发现概览

GPUToolsServices 中有**三层字典**协同完成 replay 启动与配置：

| 层级 | 字典名 | 持有者 | 用途 |
|------|--------|--------|------|
| L1 | `finalLaunchDictionary` | `DYGuestAppSession` | 底层启动字典，传给 launch strategy |
| L2 | `replayerLaunchDictionary` | `DYCaptureSession` | 专用于 replayer 的启动字典（L1 的子集/变体） |
| L3 | `traceConfigurationDictionary` | `DYGuestAppSession` 内部构建 | profiling/trace 运行时配置，通过 transport 发送 |

`hardwareCountersConfiguration` 是一个**独立 NSDictionary**（ivar），但它的值最终会被作为 L3 字典中 `_kDYTraceProfilingHardwareCountersConfigurationKey` 键的值写入。

### 关键观察

- `_kDYGuestAppLaunchCapture`、`_kDYGuestAppLaunchDiagnostics`、`_kDYGuestAppLaunchReplayer` 三个布尔键**直接对应** DYCaptureSession 的三个 ivar：
  - `_shouldLoadCapture`
  - `_shouldLoadDiagnostics`  
  - `_shouldLoadReplayer`
- VisionOS 变体是 L1 的**缩减版**（仅保留平台、环境、启动参数、UUID + 三个布尔开关）

### replayerLaunchDictionary 在 DYCaptureSession 上的其他关联 ivar

## 8. 三层字典的组装流程总结

```
DYGuestAppSession
│
├── _makeLaunchDictionary() → L1 (10 键)
│       └── 通过 registerFinalLaunchDictionaryMutator: 可追加/修改
│       └── 存入 _finalLaunchDictionary
│
├── _buildReplayerLaunchDictionaryForVisionOS() → L2 (7 键, L1 缩减版 + bool 开关)
│       └── 存入 DYCaptureSession._replayerLaunchDictionary
│
├── _sendTraceConfiguration() → L3 (7 键)
│       └── 包含 _kDYTraceProfilingHardwareCountersConfigurationKey 
│       └── hardwareCountersConfiguration 作为嵌套字典值
│       └── 通过 transport 发送给 replayer 进程
│
└── _sendAllConfigurations()
        ├── _sendTraceConfiguration()
        ├── _sendOverridesConfiguration()
        └── _sendAdditionalConfigurations()
```

## 9. 静态比对结论

### replayerLaunchDictionary 最小必要字段

对于 headless replay（`GTMTLReplay_CLI` 路径），**不需要** `replayerLaunchDictionary`。该字典仅在走 XPC/DYGuestAppSession 通路时有意义。

但若需要模拟 Xcode 的 replayer 启动行为，最小字段集为：

```objc
@{
    kDYGuestAppLaunchReplayer: @YES,           // 必须: 加载 replayer
    kDYGuestAppLaunchUUIDKey: @(uuid_hash),    // 必须: 会话标识
    kDYGuestAppPlatformPrefixKey: @"macosx",   // 必须: 平台
    kDYGuestAppLaunchEnvironmentKey: @{},      // 可选: 环境变量
    kDYGuestAppLaunchArgumentsKey: @[],        // 可选: 启动参数
}
```

### hardwareCountersConfiguration 最小字段集（推测，需 R3 验证）

```objc
@{
    @"CounterSampleBufferCounterSetName": @"GPUCounterSet_StageUtilization",
    @"CounterSampleBufferSampleCount": @(1024),
}
```

### 对 R2 bridge 原型的指导意义

1. **headless replay 路径不需要 replayerLaunchDictionary**：`GTMTLReplay_CLI` 接受 `.gputrace` 路径 + options 结构体，完全绕过 DY* 对象图
2. **如果需要通过 DY 对象图触发 replay**：需要组装 L1+L2+L3 三层字典 → 复杂度高，建议推迟到 R3
3. **profiling 配置通过 L3 字典注入**：`profilingFlags` 和 `hardwareCountersConfiguration` 都在 `_sendTraceConfiguration()` 中发送
4. **GTMTLReplayCLIOptions 与 L3 字典有对应关系**：CLI 路径下 profilingFlags 直接写入 options 结构体，无需 L3 字典
