## 1. 交付物

### 1.1 新增 wrapper 子命令 `draw-info`

```bash
python3 gputrace_replay_wrapper.py draw-info <trace> <draw_index> [--with-uniforms] [--output-dir DIR] [--pretty]
```

输出：单 draw 的扁平 JSON，binding 表已自动注入 `ir_arg_name` / `ir_arg_type_name` / `ir_arg_size` / `size_check`。

### 1.2 AIR Metadata Parser

纯 Python，基于正则表达式从 `.ll` 文件提取：
- `air.buffer` → `{location_index, arg_name, arg_type_name, arg_type_size}`
- `air.texture` → `{location_index, arg_name, arg_type_name}`
- `air.sampler` → `{location_index, arg_name, arg_type_name}`

### 1.3 size_check 计算

| 取值 | 条件 |
|------|------|
| `ok` | `available >= ir_arg_size && available <= 4 × ir_arg_size` |
| `under` | `available < ir_arg_size` |
| `over` | `available > 4 × ir_arg_size` |
| None | 信息不足（buffer_length 未知） |

### 1.4 library_key → AIRMetadata 缓存

实例级 `_air_metadata_cache: dict[int, AIRMetadata]`，同一 library 多 draw 共享不重复 disasm。

## 2. 实现架构

```
draw-info <trace> <draw_index>
    │
    ├── 1. frame-list --with-bindings → 目标 draw 的 bindings + rps_key
    │
    ├── 2. pipeline → rps_key 的 vertex/fragment library_key
    │
    ├── 3. disasm --with-ir (per library, cached) → .ll IR 文件
    │
    ├── 4. parse_air_metadata(.ll) → slot → {arg_name, type_name, size}
    │
    └── 5. enrich_stage_bindings() → 注入到 JSON + 计算 size_check
```

**Zero bridge changes** — 纯 wrapper 层实现，复用现有 9 子命令。

## 4. 设计决策

| 决策 | 理由 |
|------|------|
| wrapper-only，bridge 零变更 | R8.1 是纯组合现有数据源（frame-list + pipeline + disasm），无需在 ObjC 层增加新的 swizzle 或 API |
| AIR metadata 从 .ll 文件正则解析 | .ll 是 llvm-dis 的标准输出，格式稳定；直接解析 bitcode 需要链接 llvm-c，成本高 |
| 缓存以 library_key 为键 | 同一 library 服务多个 RPS/draw（LYSK 96 libraries → 65 RPS → 244 draws），缓存命中率高 |
| size_check 阈值 4× | 经验值：ScratchBuffer 类大 section（4MB）vs cbuffer 336B = 12000×，明显 "over"；正常独占 buffer（144B binding 给 136B cbuffer）= ~1×，明显 "ok" |
| vertex stage_in 不算 join 失败 | 后续 R8.1b 可通过 `air.vertex_input` metadata 补全，当前 MVP 先标记 |

---

## 5. 已知局限（R8.1 MVP scope 内不处理）

1. **vertex stage_in 输入不注入 metadata** — 需从 `air.vertex_input` 元数据路径解析，R8.1b 可补
2. **size_check 需要 buffer_length** — 当前 frame-list 只输出 resource_id + offset，不含 buffer_length。需要联合 `replay --list-resources` 或利用 dump-uniforms 的 buffer_length 字段。draw-info 当前在有 resource_info 时才算 size_check
3. **argument buffer 二级 indirect** — 不展开（与 R7.6-B 已知局限对齐）
4. **push constant / inline buffer** — `resource_id=null` 时 `ir_arg_name` 仍可填（已实现），但 size_check 无意义
