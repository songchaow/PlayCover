## 0. 任务前置上下文

R7.6-C 在 2026-05-21 早些时候完成，交付 `shader-of-drawcall <draw_index> --with-ir` 一行命令。但 LYSK 主基线 trace（`capture_20260518_110050.gputrace`，96 个 `_MTLLibrary`）上的 IR 命中率仅 ~3%（3/96 个 library 携带 `bitcodeData`）。其余 95%+ 请求会得到 `ir_error: "no_air_bitcode"` — 刚交付的"一行命令拿 IR"承诺在主样本上几乎无法兑现。

## 1. 目标与设计选择

**目标**：把 R7.6-C 主样本 IR 命中率从 ~3% 拉到接近 100%，让"一行命令拿 IR"在 LYSK 这种 PlayCover 启动过的主流 trace 上真正可用。

**关键观察**：PlayCover 在 `~/Library/Containers/io.playcover.PlayCover/ShaderDebugInfo/<bundle_id>/<cacheKey>/modules/<sha256>/module.bc` 落盘的 LLVM bitcode 与 trace 内 `MTLLibrary.bitcodeData` 等价（同一编译流程的副本），**且 cacheKey 与 trace 内 metallib 字节使用同一个 PlayTools FNV-style 算法计算**。所以只要 trace 的 metallib 能拿到（`pipeline` / `shader-of-rps` 早就支持），就能算 cacheKey，再到 SDI 路径找 `module.bc`。

**设计决定 — 不解析 bundle_id**：
- trace 内的 `metadata` plist 不存 bundle_id（实测 LYSK trace 仅有 `(uuid)`、`DYCaptureSession.*`、`DYCaptureEngine.*` 字段）。
- 路径解析方式（如假设 trace 在 `Containers/<bundle>/Data/Documents/Captures` 下）不稳健 — 用户可能把 trace 拷贝到 `~/Desktop`，或 PlayCover 内 trace 不在游戏容器下。
- **最优策略**：直接遍历 `~/Library/Containers/io.playcover.PlayCover/ShaderDebugInfo/*/<cacheKey>/modules/*/module.bc`，取第一个匹配。cacheKey 已含 metallib 字节长度后缀（例：`5368B920C0D59DE1_11041`），跨 app 哈希碰撞概率统计可忽略。
- 副作用：`sdi_bundle_id` 字段从扫描结果反向得出，对用户依然是有用的诊断信息（让用户确认 IR 来源）。

**设计决定 — wrapper 不强制重做关键路径**：bridge 内部统一一个 `emit_ir_for_library()` helper（library_key + airData + cacheKey + outputDir + with_ir），同时被 `cmd_shader_of_rps`（重构）与新的 `cmd_disasm` 复用。这样新能力立即顺带覆盖 `shader-of-rps` / `shader-of-drawcall` — 无需用户改命令。

## 2. 实现清单

### 2.1 bridge（`Scripts/gputrace_replay_bridge.m`，0.4.0 → 0.5.0）

新增（约 +200 行）：

| 函数 | 作用 |
|------|------|
| `sdi_root_path()` | 返回 `$HOME/Library/Containers/io.playcover.PlayCover/ShaderDebugInfo` |
| `find_sdi_module_bc(cacheKey, &bundleId, &moduleHash)` | 遍历 SDI 根目录所有 `<bundle>/<cacheKey>/modules/<hash>/module.bc`，返回第一个匹配。`outBundleId` / `outModuleHash` 反向带出 |

## 5. 已知局限 / 后续工作

1. **`<hash>` 多个候选**：SDI 目录里同一 cacheKey 下可能有多个 `<sha256>/module.bc`（理论上为不同 entry-point 变体）。当前 R7.7 v1 是"取第一个"策略；LYSK 实测下每个 cacheKey 目录都只有一个 hash，未碰到歧义。如未来碰到多 hash，第二版可按 metallib 内 function name 与 `module.meta.json.functionNames[]` 匹配。
2. **跨 bundle 路径假设**：实现遍历所有 `<bundle>/` 目录而非锁定到单一 bundle。如果用户在多 app 共用同一台机器、且不同 app 编译出 metallib 字节恰好碰撞 cacheKey，理论上会取到错误版本。**实际**：cacheKey 含 metallib 长度后缀，且 FNV-style 哈希分布，跨 app 碰撞概率统计可忽略；如未来有用户报告，可在 R7.7 v2 加 `--sdi-bundle-id` flag 显式覆盖。
3. **SDI 缓存清理**：用户清过 PlayCover 缓存后 `module.bc` 不在 → R7.7 会降级为 `no_air_bitcode_and_no_sdi` 软失败 + hint "run the app once through PlayCover to populate ShaderDebugInfo"。是真"不可达"，文档已说明。
4. **bundle_id 解析功能**：原计划在 bridge 内加 `replay --bundle-id`，但因 SDI 路径扫描方式无需 bundle_id，**省略此项**。如未来需要 bundle_id 用于其他场景（如直接定位 PlayCover 缓存目录），可后续按需加，不阻塞 R7.7 主线。
