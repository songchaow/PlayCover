## 2. 架构发现

### 2.1 ShaderDebug 请求类族

```
GTReplayShaderDebugRequest (super: GTReplayRequest)
├── GTReplayShaderDebugKernel       — compute shader 调试
│     @property minThreadPositionInGrid  (MTLSize)
│     @property maxThreadPositionInGrid  (MTLSize)
├── GTReplayShaderDebugFragment     — fragment shader 调试
│     @property minPixelPosition  (GTPoint2D={uint64,uint64})
│     @property maxPixelPosition  (GTPoint2D={uint64,uint64})
│     @property minSampleID / maxSampleID  (uint32)
│     @property renderTargetArrayIndex  (uint32)
├── GTReplayShaderDebugVertex       — vertex shader 调试
│     @property vertexIDs  (NSArray)
│     @property instanceID / amplificationID  (uint32)
├── GTReplayShaderDebugMesh         — mesh shader 调试
├── GTReplayShaderDebugObject       — object shader 调试
└── GTReplayShaderDebugPostTessellationVertex
```

公共属性（GTReplayShaderDebugRequest）：
- `dispatchUID` — `(?={?=ii}Q)` — 目标 dispatch（encoder+call index + stream）
- `programData` — `NSData` — shader binary（metallib 或 AIR）
- `programDataVersion` — `int`
- `completionHandler` — `@?` — 异步回调 block

### 2.2 Service 调用路径

```
GTMTLReplayService.shaderdebug:(GTReplayShaderDebugRequest) → GTReplayRequestToken
  ↓ (异步)
GTLLVMHelper (via Unix socket /tmp/unixsocketipc_gtd)
  ↓
GTReplayResponse.data (NSData — 执行轨迹)
```

### 2.3 关键类

| 类 | 角色 |
|---|---|
| `GTMTLReplayServiceObserver` (super: GTServiceObserver) | 异步结果观察者 |
| `GTReplayResponse` | 响应容器：version + requestID + data(NSData) + error |
| `GTReplayResponseStream` | 流式响应（state 字段） |
| `GTReplayRequestToken` | 异步令牌：tokenId, completed, pause/resume/cancel |
| `GTShaderProfilerStreamData` | 48+ 属性的完整 profiler 数据容器 |

## 3. 验证结果

### 3.1 Service 构造 ✅

```objc
// 最小 GTMTLReplayClient：只需 pool + controller
void *clientBuf = calloc(1, 2048);
*(void **)clientBuf = pool;          // offset 0: apr_pool_t*
*(void **)(clientBuf + 8) = controller; // offset 8: GTMTLReplayController*

id service = [[GTMTLReplayService alloc] initWithContext:clientBuf];
// → 成功创建 service 实例
```

### 3.2 请求提交 ✅

```objc
id token = [service shaderdebug:request];
// → 返回 GTReplayRequestToken (tokenId=1)，无异常
```

### 3.3 异步完成 ❌

- Token 永远不完成（`completed = NO`）
- CompletionHandler 永远不被调用
- 8 秒 runloop pumping 无效果

**根因**：GTMTLReplayService 的 shaderdebug 处理需要到 GTLLVMHelper 进程的 IPC 连接。
最小 client 缺少：
1. Unix socket 连接到 `/tmp/unixsocketipc_gtd`
2. GTMTLReplayOperationQueues（dispatch 队列）
3. 内部消息路由（GTTransportMessage_replayer）

### 3.4 load:error: ❌

```objc
[service load:traceURL error:&err]; // → returned NO
```
load 失败——可能需要完整 client context。

### 3.5 Observer 注册 ✅

```objc
id observer = [[GTMTLReplayServiceObserver alloc] init];
uint64_t obsId = [service registerObserver:observer]; // → 1
```
Observer 注册成功但无结果推送（因为 IPC 未连接）。

## 5. 替代方案：Instrumented Shader Debugging

虽然原生 GTLLVMHelper shader debugger 需要 IPC 连接，但我们可以通过已验证的能力组合实现等效的"printf debugging"：

### 5.1 方案描述

```
原始 shader (no source) → 提取 metallib (R5.1)
                         → 反编译为 LLVM IR (xcrun metal-objdump)
                         → 手动/自动修改 IR 注入 debug 输出
                         → 编译为新 metallib (xcrun metallib)
                         → setLibrary:forKey: 替换 (R5.2)
                         → rewind + playAll
                         → 读取 debug buffer 输出 (R4.3)
```

### 5.2 能力对照

| Xcode Shader Debug 能力 | 我们的替代方案 | 状态 |
|------------------------|-------------|------|
| 选中像素/线程 | playTo 指定 call + 指定 buffer index | ✅ |
| 查看变量值 | 注入 out[gid] = variable 到 debug buffer | ✅ |
| 单步执行 | 在不同位置注入 debug 输出，多次 replay 对比 | ✅ (多 pass) |
| 执行轨迹 | 注入 counter 到 debug buffer 记录执行路径 | ✅ |
| 无源码支持 | shaderIR path — 直接操作 metallib binary | ✅ |
| 实时交互 | ❌ 需多次 replay | ⚠️ 非实时 |

### 5.3 无源码 shader 的调试流程

1. **导出 metallib**：`objectMap.libraryForKey:` → `libraryDataContents`
2. **反汇编**：`xcrun metal-objdump -disassemble library.metallib`
3. **提取 AIR**：`objectMap.libraryForKey:` → `bitcodeData`  
4. **反编译 IR**：`xcrun metal-objdump -source library.air` 或 `llvm-dis`
5. **修改 IR**：注入 debug store 指令
6. **重编译**：`xcrun metal-lld` + `xcrun metallib`
7. **注入**：`newLibraryWithData:` + `setLibrary:forKey:`
8. **验证**：`rewind` + `playAll` + 读取输出

## 6. 关于连接 GTLLVMHelper 的可行性分析

GTLLVMHelper 通过 Unix socket (`/tmp/unixsocketipc_gtd`) 与 Xcode 通信：
- 协议：GTTransportMessage_replayer（自定义协议，带 serial/replySerial/attributes/payload）
- 认证：可能需要与创建者进程匹配
- 风险：连接可能干扰 Xcode 当前 replay（违反全局约束）

**结论**：不建议在生产中直接连接 Xcode 的 GTLLVMHelper。
如果未来需要，可考虑自行启动独立 GTLLVMHelper 实例。

## 8. 结论

**R5.3 Shader Debug — 原生路径受限，替代方案完全可行。**

- ❌ 原生 GTLLVMHelper shader debugger：需要 IPC 连接，最小 client 不满足
