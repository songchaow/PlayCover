## 2. R6.2b：Python CLI Wrapper

**任务**：封装 bridge 5 子命令为 Python 结构化接口。
**产出**：`Scripts/gputrace_replay_wrapper.py`（~700 行，Python 3.10+，仅标准库 dataclass + subprocess + json）。

### 2.1 双接口

```python
# 模块模式
from gputrace_replay_wrapper import ReplayBridge
bridge = ReplayBridge()                 # 自动定位 binary（同目录搜索）
bridge = ReplayBridge("/path/to/binary") # 指定路径

result = bridge.replay(trace, playto=N, list_resources=True)
```

```bash
# CLI 模式
python3 gputrace_replay_wrapper.py help --pretty
python3 gputrace_replay_wrapper.py replay <trace> --list-resources --pretty
python3 gputrace_replay_wrapper.py pipeline <trace> <output_dir>
python3 gputrace_replay_wrapper.py shader <trace> <key> <metallib> --verify
python3 gputrace_replay_wrapper.py config <trace> disableOptimizeRestores=0
```

### 2.2 方法签名与返回值

| 方法 | 返回类型 | 对应子命令 |
|------|---------|-----------|
| `bridge.help()` | `HelpResult` | help |
| `bridge.replay(trace, playto=N, list_resources=True, ...)` | `ReplayResult` | replay |
| `bridge.pipeline(trace, output_dir)` | `PipelineResult` | pipeline |
| `bridge.shader(trace, lib_key, metallib_path, verify=True)` | `ShaderResult` | shader |
| `bridge.config(trace, disable_optimize_restores=False, ...)` | `ConfigResult` | config |

dataclass 模型：`HelpResult` / `ReplayResult` / `Resource` / `PipelineResult` / `Library` / `ShaderResult` / `ConfigResult`。

### 2.3 错误映射

| 异常 | 场景 | 退出码 |
|---|---|---|
| `FileNotFoundError` | .gputrace 路径不存在 | 2 |
| `ValueError` | 不是 .gputrace / 缺参数 | 2 |
| `BridgeError` | bridge 返回非 0 | 原始码 |
| `TimeoutError` | 执行超时 | 124 |

### 2.4 关键特性

- 自动定位 bridge binary
- 参数校验（路径存在性、`.gputrace` 后缀、必需参数）
- JSON 输出解析为 dataclass
- 退出码映射为描述性错误名
- stderr 捕获
- 超时控制（默认 5 分钟）
- `--pretty` pretty-print
- 纯标准库实现

## 3. Skill Packaging — `gpu-trace-analysis`

**任务**：把 GPUTraceReplayAutomation 的产出打包成独立、自包含的 skill，用于 gputrace 分析与渲染问题调查。
**产出**：`.codebuddy/skills/gpu-trace-analysis/`，端到端验证通过。

### 3.1 目录结构

```
gpu-trace-analysis/
├── SKILL.md                              # YAML frontmatter + 调查工作流
├── scripts/
│   ├── .gitignore                        # 排除构建产物
│   ├── Makefile                          # skill 内嵌构建配置
│   ├── gputrace_replay_bridge.m          # ObjC bridge 源码（拷贝）
│   ├── gputrace_replay_wrapper.py        # Python wrapper（拷贝）
│   ├── setup.sh                          # 幂等构建脚本
│   └── test_bridge.sh                    # 集成测试（拷贝）
└── references/
    ├── cli-reference.md                  # CLI / Python API 参考
    ├── investigation-playbook.md         # 6 类常见渲染 bug 调查模式
    └── architecture.md                   # 技术原理 + 故障恢复
```

总大小：参考文档 ~36 KB Markdown + 脚本/源文件 ~80 KB。

### 3.2 设计原则：自包含

- 所有源码、构建配置、测试脚本**拷贝**（不软链接）到 `scripts/`
- skill 内嵌的 Makefile 不引用 workspace 路径，只用相对路径与 `$(SCRIPT_DIR)`
- `setup.sh` 用 `cd "$(dirname "$0")"` 保证从任意目录调用都能正确定位
- Python wrapper 已设计为同目录搜索 binary

**自包含验证**（在 `/tmp` 下执行）：
- `bash $SKILL_DIR/scripts/setup.sh` — 从零构建成功
- `test_bridge.sh` — 17/17 通过
- 用 wrapper replay 真实 trace — 4 resources / 0.21ms

### 3.4 Pushy description（对抗 LLM undertriggering）

description 显式枚举触发场景（black screen / missing geometry / wrong colors / broken material / flickering / shader issue / NaN / validation error / GPU hang / performance regression），并指示在出现 `.gputrace` 路径、Xcode GPU capture、Metal frame debugger、AGX shaders 时主动触发。

### 3.5 工作流引导

SKILL.md 的核心是 5 步调查循环：
1. Establish a baseline（先确认 trace 自身能 replay）
2. Frame the question（按问题类型选子命令）
3. Drill down with the right subcommand
4. Iterate（数据驱动，不靠猜）
5. Report findings（具体 JSON 字段 + 复现命令 + 一段理论）

加 5 条 operational guardrails：read-only by default、Xcode 共存、平台限制、HW counters 出范围。
