## 2. 反汇编深度分析

### 方法
在运行时通过 dlsym 获取函数地址，直接扫描 ARM64 机器码。

### 关键发现

#### 2.1 函数规模
- `GTMTLReplay_CLI` 函数体 **45484 字节**（~11000 条指令）
- RET 在 +45484

#### 2.2 callback (x2 → x20) 生命周期
```
入口:  MOV x20, x2       (+40)  — callback 保存到 x20
       STP x20, x19, [SP, #80] (+24) — 保存到栈帧
使用:  MOV x0, x20 → BL objc_retain  (+3376..+3984, 共 9 次)
       MOV x0, x20 → BL objc_release
覆盖:  LDR x20, [x8, #3920]   (+4104) — x20 被重用
结论:  callback 只被 retain/release，从未被 BLR 调用，从未作为参数传递
```

**搜索证据**：
- 0~65536 范围内无 BLR x20
- 0~4104 范围内无 STR x20 到对象
- 0~4104 范围内无 MOV x1/x2/x3, x20（不作为参数传递）

#### 2.3 Options 结构体实际访问模式

函数从 x23 (options) 读取的字段：

| 位置 | 指令偏移 | 含义 |
|------|---------|------|
| options + 0x318 | +2508 | **子对象指针**（x23 被覆盖为此值！） |

+2508 之后 x23 指向子对象，后续读取：

| 子对象偏移 | 函数偏移 | 大小 | 推测含义 |
|-----------|---------|------|---------|
| +0x00 | +2512, +2700, +6380, +30876 | 64/32-bit | 状态/类型标志 |
| +0x04 | +6408, +7524 | 32-bit | loopCount（循环计数） |
| +0x08 | +28292 | 64-bit | 某个对象指针 |
| +0x0C | +7728 | 32-bit | 配置标志 |
| +0x30 | +28268 | 64-bit | 某个对象指针 |

**关键结论**：options +0xa4 (gpuStateLevel) 和 +0xb8 (profilingFlags) **在此函数中从不被访问**。

#### 2.4 generateDerivedDataPayload
- 位于 GTMTLReplay_CLI + 4288（BL 调用）
- 函数大小 2440 字节
- **无 BLR 指令**（不调用 callback）
- 接收参数：(object, 1)

#### 2.5 真实 options 结构体大小
- 函数访问 options[0x318]，说明实际结构体 **≥ 0x320 字节**
- R1.2 文档估计的 "~0xC0 字节" 是**低估**（可能基于旧版本或部分分析）
- 当 options[0x318] = NULL 时，函数通过 NULL check 跳过相关逻辑

## 3. 结论

### 3.1 CLI 路径的实际能力范围

在 GPUToolsReplay 314.12 (macOS 26.4.1, Tahoe) 中：

| 能力 | CLI 路径 | XPC 路径 |
|------|---------|---------|
| 基础 replay 执行 | ✅ | ✅ |
| 返回成功/失败码 | ✅ (返回 int) | ✅ |
| completionCallback 数据 | ❌ (dead code) | N/A |
| Profiling 输出 | ❌ (不读 profilingFlags) | ✅ (profile: method) |
| Fetch 数据 | ❌ | ✅ (fetch: method) |
| DerivedCounters | ❌ (调用 generate 但不输出) | ✅ (query: method) |
| Shader 替换 | ❌ | ✅ (update: method) |

### 3.2 关于 +0x28/+0x30 字段
这两个字符串字段确实被 CLI 函数读取（+28268/+28292 附近），用于内部日志路径，但不直接产出用户可见输出。它们对于避免 NULL crash **仍然是必需的**。

### 3.3 策略影响
- **R3.3 目标不可达**（CLI 路径设计上不产出 profiling/callback 数据）
- **R4 Fetch/Query 路径需要通过独立 API 调用**而非 CLI 参数
- CLI 路径的价值：**确认 replay 能成功执行**（数据源完整、Metal pipeline 可编译）
- 后续数据获取需用 `GTMTLReplayHost_*` 系列 C 函数或直接操作 replay controller
