## RC-009：延迟注入方案

### 一、任务目标

将 `libmtlcapture.dylib` 的注入时机从 **启动期 `DYLD_INSERT_LIBRARIES`** 改为 **运行时 `dlopen` 按需加载**，解决部分 app（如原神）因 `GPUToolsCapture` 启动期 hook 导致崩溃的兼容性问题。

---

### 二、前置条件

**本任务依赖 `RC-010` 的验证结果。**

如果 RC-010 证明 `dlopen` 后 `supportsDestination(.gpuTraceDocument)` 可以变为 `true`，本任务才有实施价值。

---

### 三、问题背景

当前注入方式（`DYLD_INSERT_LIBRARIES=/usr/lib/libmtlcapture.dylib`）的问题：

- `DYLD_INSERT_LIBRARIES` 在进程 **最早期（dyld 阶段）** 加载库
- `GPUToolsCapture` 一旦加载，会 **全局 hook `CAMetalLayer` 的初始化路径**
- hook 代码（`MakeLayerInfos`）对 layer 对象调用某些 selector
- 部分 app（如原神）使用的 layer 子类 / 代理不响应这些 selector → `doesNotRecognizeSelector` → `abort()`
- 这是启动期同步崩溃，app 代码无法捕获

---

### 四、方案设计

#### 4.1 Host 侧（PlayCover / PlayCoverMCP）

**移除 `DYLD_INSERT_LIBRARIES` 注入。**

修改文件：
- `PlayCover/Model/PlayApp.swift`：`effectiveLaunchEnvironment()` 中删除 `DYLD_INSERT_LIBRARIES` 设置
- `PlayCoverMCP/HostServices/Launch/LaunchService.swift`：`effectiveLaunchEnvironment()` 中删除同样逻辑

注意：`metalCaptureEnabled` 设置仍保留作为 runtime 侧 `MetalCaptureService` 的开关。

#### 4.2 Runtime 侧（PlayTools）

**在 `MetalCaptureService` 中新增延迟加载能力。**

修改文件：
- `Carthage/Checkouts/PlayTools/PlayTools/MetalCaptureService.swift`

关键代码：

```swift
import Darwin  // for dlopen

private static var gpuToolsCaptureLoaded = false
private static let gpuToolsCaptureLibrary = "/usr/lib/libmtlcapture.dylib"

/// 按需加载 GPUToolsCapture 库。
/// 延迟到首次截帧 / 状态查询时才加载，避免启动期 hook 导致不兼容 app 崩溃。
private func ensureGPUToolsCaptureLoaded() -> Bool {
    guard !Self.gpuToolsCaptureLoaded else { return true }
    
    guard FileManager.default.fileExists(atPath: Self.gpuToolsCaptureLibrary) else {
        logStatusProbe("gpuToolsCaptureLibrary not found at \(Self.gpuToolsCaptureLibrary)")
        return false
    }
    
    let handle = dlopen(Self.gpuToolsCaptureLibrary, RTLD_NOW)
    Self.gpuToolsCaptureLoaded = (handle != nil)
    
    if Self.gpuToolsCaptureLoaded {
        logStatusProbe("dlopen(\(Self.gpuToolsCaptureLibrary)) succeeded; refreshing captureManager")
        captureManager = MTLCaptureManager.shared()
    } else {
        let error = String(cString: dlerror())
        logStatusProbe("dlopen(\(Self.gpuToolsCaptureLibrary)) failed: \(error)")
    }
    
    return Self.gpuToolsCaptureLoaded
}
```

调用点：
- `captureFrame()` 开头
- `getStatus()` 中（可选，取决于 Q1 验证结果）

#### 4.3 `initialize()` 的时序调整

当前 `initialize()` 在 app 启动早期被调用，会执行：
- `captureManager = MTLCaptureManager.shared()`
- `installQueueDiscoveryIfNeeded()`（swizzle `newCommandQueue`）

如果 RC-010 的 Q1 验证显示 **`MTLCaptureManager` 在首次查询时缓存了 `supportsDestination` 结果**，则可能需要：
- 在 `initialize()` 中 **不** 获取 `captureManager`
- 推迟到 `ensureGPUToolsCaptureLoaded()` 成功后才获取
- queue discovery swizzle 可以保留在 `initialize()` 中（不依赖 `libmtlcapture.dylib`）
