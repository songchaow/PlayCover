# R2.1 执行记录：CLI / JSON Schema 设计

**执行时间**：2026-05-20 11:20–11:35  
**方法**：V1 静态扫描 + V2 动态观察（活动 replay 进程 lsof、pgrep）+ 离线 .gputrace 样本检查  
**状态**：✅ 完成

---

## 1. 设计原则

- **只读、无侵入**：全部命令仅做进程观察、文件读取、二进制 strings/nm 扫描。
- **Headless、可重复**：无需 Xcode GUI 交互；可在 CI/agent 中自动执行。
- **输出 JSON**：所有命令默认 `--json` 输出；可选 `--pretty` 格式化。
- **失败可诊断**：错误时输出结构化 error 对象（含 code + message + context）。
- **统一 CLI 入口**：单一脚本 `gputrace_bridge.py`，子命令模式。

---

## 2. 顶层 CLI 结构

```
gputrace_bridge.py <subcommand> [options]

子命令：
  scan-active-replay   观察当前活动 replay 进程与文件访问
  scan-binaries        扫描 Xcode 私有二进制模块符号与版本
  inspect-gputrace     检查 .gputrace bundle 结构与 metadata
```

### 公共选项

| 选项 | 默认 | 说明 |
|------|------|------|
| `--json` | ✅ 默认 | 输出 JSON |
| `--pretty` | off | 缩进格式化 JSON |
| `--quiet` | off | 抑制 stderr 诊断日志 |
| `--xcode-path` | 自动检测 | 覆盖 Xcode.app 路径 |

### 3.2 scan-binaries

**用途**：静态扫描 Xcode 内 GPU 调试/replay 相关私有 framework 和 plugin，提取版本、路径、关键导出符号。

**选项**：

| 选项 | 默认 | 说明 |
|------|------|------|
| `--modules MODULE,...` | all | 限定扫描模块（逗号分隔）：`GPUToolsReplay`, `GPUToolsServices`, `GPUDebugger`, `GPUToolsShaderProfiler`, `GPUToolsPlatform` |
| `--symbols` | false | 包含完整导出符号列表 |
| `--strings PATTERN` | 无 | 对匹配模块执行 `strings` 并按 pattern 过滤 |

**输出 JSON Schema**：

```json

  "type": "object",
  "properties": {
    "command": { "const": "scan-binaries" },
    "timestamp": { "type": "string", "format": "date-time" },
    "xcode_path": { "type": "string" },
    "xcode_version": { "type": "string" },
    "modules": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "name": { "type": "string" },
          "path": { "type": "string" },
          "exists": { "type": "boolean" },
          "arch": { "type": "array", "items": { "type": "string" } },
          "size_bytes": { "type": "integer" },
          "key_symbols": {
```

**预设关键符号锚点**（扫描时始终检查）：

## 5. 文件分类规则

### gputrace 文件分类

| 模式 | 类型 |
|------|------|
| `store*` | `store` |
| `device-resources-*`, `delta-device-resources-*`, `unused-device-resources-*` | `resource` |
| `startup-*-platform` | `platform` |
| `index` | `index` |
| `metadata` | `metadata` |
| `capture`, `unsorted-capture` | `capture` |
| 其它 | `other` |

### lsof 文件分类

| 模式 | 类型 |
|------|------|
| `*/store0`, `*/store*` | `gputrace_store` |
| `*device-resources*`, `*startup-*-platform*` | `gputrace_resource` |
| `*/functions.*`, `*/libraries.*` (在 com.apple.metal 缓存目录下) | `metal_cache` |
| `*.metallib` | `metallib` |
| 其它 | `other` |

### 进程角色分类

| 进程名包含 | 角色 |
|-----------|------|
| `Xcode` (主进程) | `xcode` |
| `GPUToolsReplayService` | `replay_service` |
| `GPUToolsCompatService` | `compat_service` |
| `GPUToolsAgentService` | `agent_service` |
| `GTLLVMHelper` | `llvm_helper` |
| 其它 GPU/Instruments 相关 | `other` |

## 6. 实现计划（面向 R2.2）

- 单文件 Python 3.9+ 脚本：`Scripts/gputrace_bridge.py`
- 依赖：仅标准库（`subprocess`, `json`, `os`, `plistlib`, `pathlib`, `argparse`, `datetime`）
- 入口：`argparse` 子命令分发
- 测试策略：
  - `scan-active-replay`：当前有活动 replay → 验证输出字段完整性
  - `scan-binaries`：验证 GPUToolsReplay.framework 路径和 GTMTLReplay_CLI 符号是否被找到
  - `inspect-gputrace`：使用 `~/Desktop/reference_test_inject.gputrace` 样本验证 metadata 解析

---

## 7. 对后续 R2.2/R2.3 的指导

1. **R2.2 实现时**：脚本必须纯 Python 标准库，不引入第三方依赖
2. **R2.2 必须包含 `--dry-run`**：首次实现时所有子命令默认 dry-run 模式（仅输出将执行的命令）
3. **R2.3 稳定性测试**：对同一 gputrace 样本重复调用 `inspect-gputrace`，验证输出 JSON 完全一致
4. **错误降级**：`lsof` 失败时不终止 `scan-active-replay`，仅将 `open_files` 置空并在 stderr 输出 warning
