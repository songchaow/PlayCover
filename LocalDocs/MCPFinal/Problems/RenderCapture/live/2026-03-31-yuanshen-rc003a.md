## 原神：RC-003 live 样本（2026-03-31）

### 一、任务目标

本轮只做一件事：

> **在不卸载 `原神` 的前提下，完成一次最小对照验证，判断 `gpu_trace_document_unsupported` 是否是 `QQ飞车` 特有。**

---

### 二、本轮约束

用户明确约束：

- **不允许卸载 `原神`**

因此本轮只允许做：

- 启动最新 `PlayCover.app`
- 读取已安装 app 状态
- 修改宿主 `App Settings`
- 启动 app / 创建 session / 查询 capture 状态
- 最多补一次 `capture_metal_frame`

不做：

- uninstall / reinstall
- 破坏现有 `原神` 安装

---

### 三、本轮前置确认

目标对象：

- **app**：`原神`
- **bundleId**：`com.miHoYo.Yuanshen`

本轮前先确认：

1. 最新 `PlayCover.app` 已重新构建、安装并启动
2. GUI MCP HTTP 端口 `19820` 正常监听
3. runtime 注册端口 `52741` 正常监听
4. `原神` 已安装，且 `check_playtools_installed == true`

额外安装态检查结果：

- `原神` 当前安装包的 `Info.plist` 中：**`MetalCaptureEnabled` 不存在**
- `QQ飞车` 当前安装包的 `Info.plist` 中：**`MetalCaptureEnabled == true`**

这说明：

- `原神` 不是一个“确认安装态已开启 MetalCaptureEnabled”的干净对照样本
- 但它仍然可以作为**非破坏性 live 对照样本**，用于判断当前症状是否仅发生在 `QQ飞车`

---

### 四、本轮执行步骤

按最小路径执行：

1. 对 `原神` 执行 `update_app_settings(metalCaptureEnabled=true)`
2. 确认宿主 `App Settings` 已落盘为 `metalCaptureEnabled=true`
3. `launch_app(com.miHoYo.Yuanshen)`
4. `create_session(timeout=25)`
5. `get_capture_status(sessionId=...)`
6. 仅补做一次 `capture_metal_frame`
7. 立即检查：
   - `list_sessions`
   - crash 报告目录

### 六、本轮结论

本轮已足够给出明确判断：

1. **`gpu_trace_document_unsupported` 不是 `QQ飞车` 特有现象。**
2. 在第二个真实 app `原神` 上，即使不卸载、只做非破坏性最小链路验证，仍然得到与 `QQ飞车` 一致的诊断结果。
3. 因此，当前问题更像是：
   - **当前机器级**
   - **当前 macOS / Xcode / DeveloperTools 环境级**
   - 或 **当前 PlayCover runtime 环境级**
   的普遍限制，而不是某一款 app 的专属问题。

需要保留的 caveat 是：

- `原神` 当前安装包缺少 `MetalCaptureEnabled` key，因此它不是“安装态完全干净”的 capture 样本
- 但这**不会推翻**本轮最关键判断：
  - 因为 `QQ飞车` 的安装态 key 已存在
  - 两个真实 app 仍然都返回了同一个 `gpu_trace_document_unsupported`

---

### 七、对后续任务的影响

`RC-003` 完成后，主线不应再停留在：

> “是不是只有 `QQ飞车` 不支持 capture？”

更合理的下一步是：

> **把问题转成环境级排查：为什么当前机器 / 当前 PlayCover 环境下，多个真实 app 都 `supports_gpu_trace=false`？**

建议后续优先围绕：

- `MTLCaptureManager.supportsDestination(.gpuTraceDocument)` 的环境前提
- `supports_developer_tools=false` 的真实含义
- 当前 Xcode / Developer Tools / macOS 组合是否对 `.gpuTraceDocument` 有全局限制
- 为什么 `原神` 缺少 `MetalCaptureEnabled` key 仍能返回与 `QQ飞车` 一致的状态诊断
