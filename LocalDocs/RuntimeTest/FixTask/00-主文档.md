### 一、目标与完成标准

本轮总目标：**修复 RT01–RT08，补齐测试，并完成一次面向真实 GUI / MCP / Runtime 的回归验证。**

完成标准：

1. `preview_entitlements` / `validate_app_signing` 行为可解释、可测试、互相一致
2. keymap 变更后，`list_keymaps` 与实际状态保持一致，GUI 刷新链路不再掉队
3. task JSON-RPC method、任务通知 method、对外工具层暴露三者一致且可直接使用
4. 安装链路对“不兼容 IPA”给出**更早、更清晰**的失败原因
5. host 侧会话基础设施真正启动
6. runtime 侧 `BridgeListener` 真正实现并接入 PlayTools 启动路径
7. `create_session` + touch/input/capture 至少完成一轮真实 app 端到端验证
8. 所有新增修复都有测试或脚本回归覆盖

### 六、全局注意事项

- **绝对不要卸载 `原神`**
- 可以卸载 / 安装 `QQ飞车`，但目前给定 IPA 已知会触发架构兼容性问题
- 对无效 IPA 的修复目标是：**更早失败、报错更清楚**，不是“强行让不兼容包安装成功”
- session / runtime 问题不是单点问题，至少涉及三层：
  - host bootstrap（`MCPManager.swift` / `main.swift`）
  - host listener / registry / monitor（`RegistrationListener.swift` 等）
  - runtime bridge / PlayTools 启动接线（`BridgeListener.swift` / `PlayCover.swift`）
- `MCPManager.swift` 和 `PlayCoverMCP/main.swift` 都有服务注册逻辑；改一边时要评估另一边是否也需要同步
- 改 `Carthage/Checkouts/PlayTools/` 下的代码后，**不能只看单元测试**，要确认真实 app 中的 PlayTools 代码路径也被重新构建 / 注入 / 安装到了目标 app
