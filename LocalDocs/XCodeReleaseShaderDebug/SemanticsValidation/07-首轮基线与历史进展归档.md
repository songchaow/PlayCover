### 4. 第一版 gate 判定收口

后续在代表 preset 基线上继续新增了：

- `gate-summary.json`
- `--gate-profile`
- `--enforce-gate`

当前代表 preset 的第一版语义是：

- **`PASS`**：结果落在已配置边界内，且没有活跃已知 debt
- **`WARN`**：仅存在已知 `L2 / L3 / blocked debt`，未出现新增回归
- **`FAIL`**：出现新增 round-trip failure、新增 `L3` blocker，或代表集 job 数异常变化
- 对 `daily-default` / `local-corpus-representatives`，后续又补上了 `minimumExpectedJobCount` 与 `expectedJobCount` 双边界：缺少部分本地代表样本记 `WARN`，低于硬下界或超出代表集边界才记 `FAIL`

## 历史上下文说明

### 1. 为什么主文档不再展开这些首轮样本名单

这份批量结果虽然已经不是当前默认 gate 的口径，但它仍能回答两类历史问题：

- 哪些模式在第一版 compare 里噪声最大

### 3. 为什么当前最该继续补的，不是更多历史描述，而是更稳定的控制面

若只关心当前最该推进的事，请回到 `00-Dashboard.md` 与 `02-总体技术路线.md`：主线仍是守住 `test-data-representatives` 硬默认入口，把 `daily-default / local-corpus-representatives` 保持为增强入口，并继续用 `SV-004F` 维持收缩后的默认行为证据边界，因此当前更该守住的是这条 `pass/pass` 默认边界与 oracle 同步性，而不是再把旧未决点重新写回主线。

作为历史对照，当前已经下沉、不必在主文档重复展开的旧 fail evidence 主要有两类：

- `test_casts`：旧 fail 的直接根因已确认是 `IRToMSLConverter` 对 `air.convert.u.*` / `air.convert.*.u.*` 的 unsigned 语义恢复不足；修复后它已退出活跃 `L2` 债务，并只保留为定向复核样本
- `test_intrinsic_vector_icmp_zext`：旧 fragment `fail` 已确认不是新的 lowering 回归，而是 reference sample 与 `.ll` 输出语义漂移导致的 sample oracle 噪声；把 `cmp/zext` 重新接回可观察输出并复跑后，最小 render-second 已回到稳定 `pass`

这些经过继续保留在归档层，便于回查，但当前主线推进**不必须反复读取**。
