# 任务分解与执行顺序

## 依赖关系图

```
G01 解决命名冲突
 │
 ├──→ G02 MCP 源文件加入 GUI target（需要先解决冲突才能编译）
 │      │
 │      ├──→ G03 TCPTransport 实现（需要 MCP Protocol 层在 GUI target 可用）
 │      │      │
 │      │      └──→ G04 MCPManager 生命周期管理（依赖 TCPTransport）
 │      │             │
 │      │             └──→ G05 GUI-MCP 状态联动（依赖 MCPManager 可工作）
 │      │                    │
 │      │                    └──→ G06 UI 状态指示（可选）
 │      │
 │      └──→ G07 Agent 侧配置 + 文档更新（可在 G04 之后并行）
 │
 └──→ G08 端到端集成测试（最后）
```

## 任务列表

### G01：解决命名冲突

**前置依赖**：无

**范围**：
- 将 MCP 的 `enum Shell` 改名为 `MCPShell`（或其他不冲突的名字）
- 更新所有 MCP 源文件中对 `Shell` 的引用
- 编译验证两个 target 都能通过

**预期改动文件**：
- `PlayCoverMCP/Common/Shell.swift`（假设在此文件定义）
- 所有引用 `Shell.xxx` 的 MCP 源文件

**验收标准**：
- `xcodebuild -scheme PlayCoverMCP build` 通过
- `xcodebuild -scheme PlayCover build` 通过
- 现有 MCP 测试全部通过

**预估**：0.5-1 天

---

### G02：MCP 源文件加入 GUI target

**前置依赖**：G01

**范围**：
- 将 MCP 的核心源文件加入 PlayCover.app target 的编译
- 排除 `main.swift`（GUI 有自己的 @main）
- 排除 `StdioTransport.swift`（GUI 不需要 stdio 模式）
- 确保编译通过，不产生链接错误

**方案选择**：
- **优先**：创建 `PlayCoverMCPCore` 共享 framework target，两个 app 都链接
- **备选**：直接修改文件的 target membership

**预期改动**：
- `PlayCover.xcodeproj/project.pbxproj`
- 可能需要新建 framework target

**验收标准**：
- GUI target 编译通过
- MCP CLI target 编译通过
- MCP 测试全部通过

**预估**：0.5 天

---

### G03：TCPTransport 实现

**前置依赖**：G02（需要 MCP Protocol 层的类型定义在 GUI target 可用）

**范围**：
- 新建 `TCPTransport.swift`
- 基于 `Network.framework`（`NWListener` + `NWConnection`）
- 仅监听 `127.0.0.1`
- 行分隔 JSON-RPC 协议
- 支持多客户端并发
- 后台线程运行，不阻塞主线程

**范围外**：
- TLS / 认证
- 远程访问
- HTTP / SSE / WebSocket（用最简单的 raw TCP）

**预期新增文件**：
- `PlayCoverMCP/Transport/TCPTransport.swift`（或 `PlayCover/Services/TCPTransport.swift`）

**验收标准**：
- 单元测试覆盖：连接/断开、消息收发、多客户端
- 可通过 `nc localhost 19820` 手动发 JSON-RPC 验证
- 不阻塞主线程

**预估**：1.5 天

---

### G04：MCPManager 生命周期管理

**前置依赖**：G03

**范围**：
- 新建 `MCPManager` 类
- 复现 `main.swift` 中的 server bootstrap 逻辑
- 在 `AppDelegate.applicationDidFinishLaunching` 中启动
- 在 `applicationWillTerminate` 中停止
- 暴露 `@Published` 状态供 UI 使用

**预期新增文件**：
- `PlayCover/Services/MCPManager.swift`

**预期修改文件**：
- `PlayCover/Views/PlayCoverApp.swift`

**验收标准**：
- 启动 PlayCover.app 后，`nc localhost 19820` 能连接
- 发送 `initialize` 请求能收到正确响应
- 退出 app 后端口释放

**预估**：0.5 天

---

### G05：GUI-MCP 状态联动

**前置依赖**：G04

**范围**：
- 定义 NotificationCenter 通知名
- 在 MCP Service 的关键操作完成后 post 通知
- 在 GUI ViewModel（`AppsVM` 等）中监听并刷新
- 覆盖操作：install、uninstall、settings、keymap、inject/remove playtools、cleanup

**预期修改文件**：
- MCP 侧多个 Service 文件（添加通知发送）
- `PlayCover/ViewModel/AppsVM.swift`（添加通知监听）
- 可能还有 settings / keymap 相关的 ViewModel

**验收标准**：
- 通过 MCP 安装应用后，GUI 列表自动刷新
- 通过 MCP 卸载应用后，GUI 列表自动更新
- 通过 MCP 修改设置后，重新打开设置界面能看到新值

**预估**：1-1.5 天

---

**前置依赖**：G05
