## Render Capture：验证入口与代码锚点

### 一、当前已知验证入口

#### 1. GUI / MCP 基础入口

- `PlayCover.app`
- GUI 内嵌 MCP HTTP：`http://127.0.0.1:19820/mcp`
- runtime 注册端口：`52741`

#### 2. 推荐验证层次

优先按下面顺序理解问题：

1. GUI / MCP 是否正常启动
2. 真实 app 是否能 `launch_app`
3. `create_session` 是否到 `ready`
4. `get_capture_status` 的核心状态字段是否合理
5. 若 `supports_gpu_trace=false`，继续看新增诊断字段
6. `capture_metal_frame` 是否真的落盘 `.gputrace`

#### 3. 当前真实测试对象

- 主对象：`QQ飞车`（`com.tencent.tmgp.speedmobile`）
- 对照候选：`原神`（`com.miHoYo.Yuanshen`）

### 五、本轮后最关键的状态字段

`get_capture_status` 现在优先关注：

- `available`
- `enabled`
- `supports_gpu_trace`
- `supports_developer_tools`
- `has_default_device`
- `default_device_name`
- `failure_reason`
- `diagnostic_summary`

`capture_metal_frame` 在失败时也应优先看 runtime 透传出来的完整错误文本，而不是只看 host 层抽象错误。

### 六、当前最关键的已知事实

截至当前，已知：

- `QQ飞车` 历史上能成功创建 `ready` session
- `metalCaptureEnabled=true`
- 已安装 app 的 `Info.plist` 中 `MetalCaptureEnabled=true`
- 历史 `get_capture_status` 返回过：
  - `available=true`
  - `enabled=true`
  - `supports_gpu_trace=false`
- 实际 `capture_metal_frame` 历史上失败，且无 `.gputrace` 落盘
- 本轮已经完成观测增强，下一轮应收集带新诊断字段的 live 样本
