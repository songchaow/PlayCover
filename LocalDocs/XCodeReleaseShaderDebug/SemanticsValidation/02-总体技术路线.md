## 总体技术路线

## 文档职责

本文只描述 `SemanticsValidation` 的**分层模型、层间关系、止损规则与推荐产物**。

**任务状态、进展、优先级、TODO、完成判定与默认执行顺序统一只在 `00-Dashboard.md` 维护。** 本页不重复动态控制面信息。

## 目标

在不打乱现有 offline-first 工作流的前提下，为“语义验证”建立一条分层、渐进、可止损的证据体系。

核心思想：

- 不追求一步到位
- 先建立低成本离线证据，再逐步增加高成本证据
- 每一层都只回答自己该回答的问题
- 只有低层证据不足时，才升级到高层

## 基本约束

- 任何新路线都不应把 GUI、人工登录、工作区外修改、人工批量枚举样本或人工准备环境写回默认流程
- 日常构建、调试、测试、验证应优先保持为 agent 可独立完成的命令链路
- 结构化报告应优先作为事实载体；描述文字只能辅助解释，不能替代报告本身
- 高层验证用于补充低层证据，不能反向替代低层职责

## 四层模型

### L1：IR Round-trip 结构验证

目标：建立最小闭环：

```text
IR -> MSL -> AIR -> IR
```

回答的问题：

- 哪些样本能完成 round-trip
- 哪些样本在生成 MSL、Metal 编译或反汇编阶段失败
- 哪些样本可以继续进入结构比较

L1 提供的是**闭环能力与失败分层**，不是语义证明。

### L2：Canonical Compare + 风险分级

目标：把“文本 diff”升级为“结构化 compare + 风险分级”。

重点比较：

- entry 集合与 shader 类型
- 参数/返回摘要
- 地址空间
- builtin / resource 使用
- CFG 粗结构
- instruction family 分布
- fast-math 与关键属性

L2 提供的是**批量可运行的语义风险筛查**，不是行为 oracle。

### L3：最小行为测试

目标：在少量高价值样本上建立“固定输入 → 固定输出”的自动验证。

优先顺序：

1. compute-first
2. 必要时 render-second

L3 用于把结构风险升级为行为证据。

### L4：真实场景验证

目标：在真实 shader、真实 capture、真实 app 场景中做最终后置确认。

L4 解决的是：

- 低层证据是否足够可信
- 某些问题是否只能在 runtime / live 条件下暴露
- replacement / `.gputrace` / render 结构是否真正命中

## 层间推进原则

### 1. 先低成本，再高成本

默认顺序始终是：

```text
L1 -> L2 -> L3 -> L4
```

只有当低层无法充分回答问题时，才应进入更高一层。

### 2. 先批量，再定向

优先建立可以批量运行、结构化落盘的入口；单样本 smoke、定向 live 复核只适合作为补充动作。

### 3. 先自动化，再人工兜底

任何验证路径都应优先证明：

- 可以本地执行
- 可以脚本化
- 可以稳定落盘
- 不需要用户频繁介入

### 4. 先复用已采集样本，再考虑新增样本

样本优先顺序应是：

1. 固定代表集 / 内置测试样本
2. 本地已存在的 `ShaderCorpus`
3. 本地已导出的 `ShaderSourceDiagnostics`
4. 仅在必要时新增更高成本样本

## 与现有工作流的关系

现有主回路仍然是“真实样本采集 → 离线 replay / compile / diff → 必要时 live 复测”。

`SemanticsValidation` 新增的是一条更早暴露语义风险的离线证据支路：

```text
module.ll -> round-trip -> canonical compare -> risk grading
```

这条支路的职责是尽可能在进入高成本验证前，先把结构性风险显式化、分级化、可回归化。

## 推荐产物结构

```text
build/semantics-validation/
  roundtrip/
    <preset-or-run>/
      replay-summary.json
      compile-summary.json
      roundtrip-summary.json
      compare-summary.json
      risk-report.json
      high-risk-samples.json
      gate-summary.json
      preset-manifest.json
      # optional
      baseline.json
      generated-sources/
  behavior/
    <run>/
      behavior-summary.json
  real-scene/
    <run>/
      live-summary.json
      gputrace-summary.json
      render-diff-summary.json
      diagnostics-summary.json
```
