# R4.2 技术参考：Controller 路径 — Headless In-Process Replay Controller

**完成时间**：2026-05-20  
**方法**：V1 静态反汇编 + V4 最小样本测试  
**结论**：✅ Controller 路径完整验证成功。无需 XPC/entitlement，在进程内直接创建 replay controller 并执行 playAll

---

## 1. 完整调用链

```
apr_pool_create_ex(&pool, NULL, NULL, NULL)
    ↓
GTMTLReplayController_makeDataSource(path, pool)
    ↓ → dataSource (APR-based state machine context)
GTMTLReplaySupport_init(device)
    ↓
[[GTMTLReplayObjectMap alloc] initWithDevice:device]
    ↓ → objectMap (302 个方法，管理所有 replay GPU 对象)
GTMTLReplayController_initializeArgumentBufferSupport(dataSource, device, objectMap)
    ↓
GTMTLReplayController_populateUnusedResources(dataSource, objectMap)
    ↓
GTMTLReplayController_makeController(dataSource, pool, device, objectMap, NULL, NULL)
    ↓ → controller (完整 replay controller)
GTMTLReplayController_playAll(controller) → 0
GTMTLReplayController_rewind(controller)
```

## 3. GTMTLReplayObjectMap

302 方法的 NSObject 子类，replay 期间所有 GPU 对象的注册表：
- MTLDevice, MTLCommandQueue, MTLBuffer, MTLTexture
- Pipeline states, Libraries, Functions
- Encoders, Command Buffers
- `resources` → NSDictionary（全部资源）
- `bufferForKey:` / `textureForKey:` — 直接数据访问
- `defaultCommandQueue` — 有效 MTLCommandQueue

验证确认：playAll 后 `objectMap.resources` 为有效 NSDictionary，`objectMap.defaultCommandQueue` 为有效 MTLCommandQueue。

---

## 4. Controller 路径 vs CLI 路径

| 维度 | CLI 路径 (R3) | Controller 路径 (R4.2) |
|------|-------------|----------------------|
| 入口函数 | `GTMTLReplay_CLI` | `makeDataSource` + `makeController` |
| 能力 | 仅 replay 验证（返回 0/非 0） | 完整 replay + 对象访问 + playTo |
| 数据获取 | ❌ | ✅ 通过 objectMap |
| XPC/Entitlement | ❌ 不需要 | ❌ 不需要 |

---

## 5. GTMTLReplayController_init vs makeController

- `GTMTLReplayController_init`：XPC Service 全局初始化（设置 transport + 全局状态），CLI 从不调用
- `GTMTLReplayController_makeController`：实际创建 controller 对象（接受 dataSource+pool+device+objectMap），CLI 内部使用

---

## 6. 对后续任务的关键启示

- **R4.3 playTo**：`GTMTLReplayController_playTo` 是导出函数，可直接 dlsym 调用。参数签名待反汇编确认
