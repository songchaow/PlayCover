## RC-014：启动期注入兼容性修复（Early Compat Stubs）

### 一、任务目标

让原神在启动期注入模式（`DYLD_INSERT_LIBRARIES`）下不再 SIGABRT 崩溃，使 `GPUToolsCapture` 能在 dyld 阶段完整 hook Metal 对象，获得非空 trace。

### 二、状态

**DONE** — 启动期 SIGABRT 已修复。原神可在启动期注入模式下正常启动（关闭 MetalFX 前提下）。但 trace 仍为空 — GPUToolsCapture 未能代理原神的 Metal 命令流。

### 三、根因分析

RC-012 确认：启动期注入时 SIGABRT 崩溃路径为：
```
GPUToolsCapture.CAMetalLayer_init → MakeLayerInfos
  → device.traceStream  → doesNotRecognizeSelector → SIGABRT
  → layer.streamReference → doesNotRecognizeSelector → SIGABRT
```

RC-012 的 NSObject fallback stubs 只在 `MetalCaptureService.ensureGPUToolsCaptureLoaded()` 中安装（延迟 dlopen 路径），启动期注入时不会执行——因为 `GPUToolsCapture` 在 dyld 阶段就已加载和 hook，而 `ensureGPUToolsCaptureLoaded()` 要到截帧时才被调用。

### 四、方案

在 `GuardedCapture.m` 中添加 `__attribute__((constructor))` 函数，在 **dyld 加载 PlayTools 时立即** 安装 `traceStream`/`streamReference` 的 nil-returning fallback stubs 到 `NSObject`。

**时序分析**：
1. dyld 处理 `DYLD_INSERT_LIBRARIES` → `libmtlcapture.dylib`（GPUToolsCapture）加载，hook `CAMetalLayer` 初始化
2. dyld 加载 app 的 LC_LOAD_DYLIB → PlayTools.framework 加载 → **`guardedCapture_earlyInit()` constructor 执行，安装 stubs**
3. App main() 执行 → 创建 UI / Metal 对象
4. `CAMetalLayer` 初始化触发 `MakeLayerInfos` → `traceStream`/`streamReference` 命中 stubs 返回 nil → **不再崩溃**

### 五、代码改动

1. **`GuardedCapture.h`**：添加 `PlayTools_installGPUToolsCaptureEarlyStubs()` 声明
2. **`GuardedCapture.m`**：
   - 新增 `guardedCapture_nilReturningStub()` — nil-returning IMP
   - 新增 `PlayTools_installGPUToolsCaptureEarlyStubs()` — 安装 stubs 到 NSObject
   - 新增 `guardedCapture_earlyInit()` — `__attribute__((constructor))` 自动调用
3. **`MetalCaptureService.swift`**：`installGPUToolsCaptureCompatStubs()` 增加对 `PlayTools_installGPUToolsCaptureEarlyStubs()` 的调用作为安全网

### 六、验证结果（2026-04-01 00:44 ~ 00:48）

### 七、关键发现

1. **RC-014 成功修复了启动期 SIGABRT** — `traceStream`/`streamReference` stubs 在 dyld 阶段就位
2. **MetalFX 是额外不兼容点** — 需在游戏中关闭 MetalFX 才能在启动期注入模式下运行
3. **trace 仍然为空** — 即使启动期注入，原神的 Metal 命令流未被 `GPUToolsCapture` 拦截
   - 证据：tracked queue class 是 `AGXG16XFamilyCommandQueue`，非 `CaptureMTLCommandQueue`
   - `stopCapture` 仍触发 SIGSEGV（empty trace context）
4. **根本限制**：原神的 Metal 使用方式与 `GPUToolsCapture` 的代理架构不兼容
   - 不仅是 `CAMetalLayer` hook 问题
   - 而是 `GPUToolsCapture` 无法代理原神的整个 Metal 管线

### 八、兼容性矩阵更新

|---|---|---|---|---|
| QQ飞车 | ✅ | ✅ 413MB .gputrace | ✅ | ✅ 124MB .gputrace |
| 原神 | ✅ | ✅ 不崩溃，空 trace | ✅ (需关闭MetalFX) | ❌ 空 trace (GPUToolsCapture 无法代理命令流) |

### 九、结论

原神与 Apple `GPUToolsCapture` 框架**根本不兼容**。无论启动期注入还是延迟注入：
- 启动期注入：stubs 修复了 SIGABRT，MetalFX 关闭后可正常运行，但 trace 为空
- 延迟注入：正常运行但 trace 为空
- 两种模式下 `GPUToolsCapture` 均无法拦截原神的 Metal 命令流

这不是 PlayCover 可以解决的问题，而是 Apple 私有框架 `GPUToolsCapture` 对原神的 Metal 使用方式不兼容。
