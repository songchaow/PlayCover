## T05：安装链路架构预检与错误诊断

### 目标

处理 RT08 暴露出的安装链路问题：给定 `QQ飞车` IPA 最终报错为：

- `MachO conversion failed: No ARM64 architecture found in fat binary`

这个问题**不一定意味着安装器有逻辑 bug**；但当前体验确实有明显缺陷：

1. 失败暴露得太晚
2. 调用方一开始拿不到清晰根因
3. 错误对“这包本身就不兼容”表达得不够前置

本任务的目标是：**让不兼容 IPA 更早失败、错误更清晰、测试更稳定。**

### 推荐工作内容

1. 给安装链路加一个**更前置的架构 / 可执行预检**
   - 主程序是否存在
   - Mach-O 是否可识别
   - 是否包含 PlayCover 需要的 ARM64 slice
2. 把“不兼容 IPA”与“安装过程内部异常”区分成不同错误类型或不同 message
3. 如果 `injectPlayTools=true` 与 `false` 的失败原因不同，尽量让调用方能分辨
4. 为后续人工测试保留一个稳定的**负例用法**：
   - 已知无 ARM64 的 IPA 应该稳定、快速、清晰地失败

### 预检策略（已实施）

当前修复聚焦 `PlayCoverMCP` 的 `InstallerService` / `InstallerTools`：

1. 读取 `Info.plist` 后，先校验 `CFBundleExecutable` 是否存在
2. 立即确认主程序文件存在，且能被识别为 Mach-O
3. 枚举 app 内全部 Mach-O，并在**保存 entitlements / Mach-O 转换 / PlayTools 注入之前**完成架构检查
4. 任何二进制缺少 `arm64` slice 时，直接抛出专用 `unsupportedArchitecture` 错误
5. `install_ipa` / `export_patched_ipa` 的 task 失败码改为走统一 MCP 错误映射，不再把这类失败笼统归为 `exportFailed`

---

### 负例测试方式（已沉淀）

#### 1. 单元测试负例

已在 `PlayCoverMCPTests/InstallerServiceTests.swift` 增加稳定负例：

- 构造仅含 `x86_64` 的 fake fat Mach-O
- 断言 `install(...)` / `export(...)` 都会抛出 `unsupportedArchitecture`
- 断言失败发生在 `saving entitlements` 之前，保证问题被更前置地暴露

#### 2. 单元测试正例

同时保留简化 `arm64` fixture，验证预检可继续推进到后续阶段；
由于该 fixture 只是极小化测试二进制，后续可能仍在 `codesign --entitlements` 等步骤失败，这**不表示预检回退**。

#### 3. live negative test 参考（需复核）

此前曾将以下 IPA 作为 live negative test 参考：

- app：`QQ飞车`
- bundle：`com.tencent.tmgp.speedmobile`
- IPA：`/Users/songdogwang/Downloads/NSS_Debug_Test_DB_1.55.0.36877_1828878_12136_enterprise_sign_forpay.ipa`

但 2026-03-30 夜间新增 live 证据显示：

- 通过 `playcover` MCP 的 `install_ipa`，该 IPA 仍会失败，`get_task(task-1)` 返回：
  - `code = -32015`
  - `message = MachO conversion failed: No ARM64 architecture found in fat binary`

因此，这个 IPA **不再适合作为“必然不兼容 / 必然无 ARM64”的稳定负例样本**。更可能的现状是：`PlayCoverMCP` 与 GUI 原生安装路径仍存在行为不一致。
