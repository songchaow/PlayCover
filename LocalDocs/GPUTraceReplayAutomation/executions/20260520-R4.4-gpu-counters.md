## 探索路径与结果

### 路径 1：GPURawCounter.framework 直接调用

**结果：❌ BLOCKED**

```
GRCCopyAllCounterSourceGroupWithError → Error Domain=GPURawCounterErrorDomain Code=-1
"Fail to instantiate AGXGPURawCounterSourceGroup"
```

**原因**：需要 `com.apple.private.agx.performance-spi` entitlement + IOKit `AGXDeviceUserClient` 访问权限。

**谁拥有这个 entitlement**：仅 `GPUToolsReplayService.xpc`（由 Xcode 启动的 XPC 服务，pid 14881）。其完整 entitlements：
- `com.apple.private.agx.performance-spi` ← GPU counter 核心权限
- `com.apple.private.pmp.performance-spi` ← 性能监控
- `com.apple.security.temporary-exception.iokit-user-client-class: AGXDeviceUserClient`
- `com.apple.private.gputools.client`

**结论**：无签名的 headless 探针无法直接获取 GPURawCounter 数据。获取方式只有：
1. 通过 XPC 连接到 GPUToolsReplayService（但它是 Application 类型 XPC，仅宿主 Xcode 可连接）
2. 自签名并添加相应 entitlement（需要 SIP 关闭或开发者证书）

### 路径 2：Metal Counter Sets

**结果：⚠️ 有限可用**

| Counter Set | 状态 |
|-------------|------|
| `timestamp` (1 counter: GPUTimestamp) | 存在，但不支持 in-encoder sampling |

Counter sampling 支持：
| Sampling Point | 支持 |
|---------------|------|
| AtStageBoundary | ✅ YES |
| AtDrawBoundary | ❌ NO |
| AtBlitBoundary | ❌ NO |
| AtDispatchBoundary | ❌ NO |
| AtTileDispatchBoundary | ❌ NO |

`sampleCountersInBuffer` 在 MTLBlitCommandEncoder/MTLCommandBuffer 上均 abort：
```
failed assertion 'MTLBlitCommandEncoder:sampleCountersInBuffer:atSampleIndex:withBarrier not supported on this device'
```

**注意**：虽然 `supportsCounterSampling(AtStageBoundary)` = YES，但这需要 **MTLRenderCommandEncoder** 且在 render pass boundaries 使用。Replay 框架内部管理 command buffer，我们无法注入 stage boundary sampling。

### 路径 3：MTLCommandBuffer GPU Timing（始终可用）

**结果：✅ 成功**

```
MTLCommandBuffer.GPUStartTime / GPUEndTime
```

独立测试：Fill 1MB buffer → GPU time = 13.875–14.125 µs ✅

### 路径 4：Host Timing + playTo（始终可用）

**结果：✅ 成功**

通过 `mach_absolute_time()` 在 `playTo` 前后采集，获得 per-segment timing。

测试结果（capture_20260518_003517.gputrace）：

| playTo Target | Host Time (ms) | 观察 |
|--------------|----------------|------|
| 1 | 0.009 | CPU-only setup |
| 2 | 0.008 | 同上 |
| 5 | 0.016 | 少量 GPU 工作 |
| 10 | 0.015 | 类似 |
| 20 | 2.583 | **大跳变** — 某个 draw call 触发大量 GPU 工作 |
| 50 | 2.487 | GPU work 主体在 call 10-20 之间 |
| 100 | 2.548 | 之后增量很小 |
| 200 | 2.321 | playAll 全帧 = 12.631ms |

**关键洞察**：timing 跳变显示主要 GPU workload 集中在 call index 10-20 之间，这对 performance debugging 非常有价值。

## 能力矩阵

| 计数器类型 | Headless 可用性 | 获取方式 |
|-----------|----------------|---------|
| Host timing (per-segment) | ✅ | mach_absolute_time + playTo |
| GPU timing (per-cmdBuf) | ✅ | MTLCommandBuffer.GPUStartTime（独立 cmdBuf） |
| GPU timing (replay cmdBuf) | ❌ | 需拦截 replay 内部的 command buffer 提交 |
| Stage boundary timestamp | ⚠️ 理论可用 | 需在 replay render pass 内注入采样点 |
| ALU/Cache/Bandwidth counters | ❌ | 需 GPURawCounter + entitlement |
| Derived counters | ❌ | 需 XPC 到 GPUToolsReplayService |

## 阻塞分析与后续路径

**核心阻塞**：`com.apple.private.agx.performance-spi` entitlement 限制。

**可能的解除方式**（需用户确认）：
1. **Ad-hoc 签名 + entitlement 注入**：`codesign --entitlements counters.plist -s - counter_probe`（可能仍需 SIP 放行）
2. **通过 Instruments 获取**：Instruments 的 GPU 模板可采集硬件计数器，输出可解析
3. **通过活跃的 GPUToolsReplayService**：如果能逆向其 XPC 协议，可连接获取数据（但服务类型为 Application，限制外部连接）
4. **IOKit 直接访问**：`IOServiceOpen` 到 AGXDeviceUserClient（需 SIP 关闭）

**推荐**：标记 R4.4 为"部分完成"，timing 能力已可用。完整硬件计数器留待 R4.4b 在获得用户许可后探索 entitlement 签名方案。
