## 现状调研与缺口

## 目的

本文档承接当前语义验证现状的调研结论，回答两个问题：

1. **我们已经有什么？**
2. **为什么这些能力还不足以证明语义等价？**

主文档只保留结论与任务控制面；本文件保留当前现状、能力边界与缺口说明。若只是推进日常主线任务，优先读 `00-Dashboard.md` 与 `02-总体技术路线.md`；本文件按需阅读即可，当前日常推进**不必须读取**。

## 当前已确认的事实

### 1. 文档目标明确要求“语义等价”

前置任务优先级仍然是：

1. **语义等价**
2. **可编译**
3. **可读性**

这意味着这里的最终技术目标仍然不是“源码可见 / 可编译即可”，而是尽量建立更可信的语义证据。

### 2. 当前主链路已经成熟

当前 hook、bitcode 提取、`llvm-dis`、`IRToMSLConverter`、编译、replay / corpus / runtime 工具链都已具备；语义验证专项不需要重建基础设施，重点是把已有链路收口成稳定、低心智负担、低人工依赖的默认验证入口。

### 3. 当前已有的工程保证

当前已经具备：逐指令机械翻译、LLVM token 卫生检查、可编译性守门，以及 replay / compile / baseline diff / `.gputrace` 检查 / render-structure diff 等工程保障。

这些能力足以提供结构化证据，但仍不足以单独证明语义等价。

### 4. 当前阶段更适合把它当作“前置任务完成后的深化验证”来看

因此当前 active work 的重点已经不再是“有没有第一版 L3 harness”，而是**把已采集 corpus 样本尽可能纳入 L1/L2 的自动化离线路径**，并确保这条路径不会重新引入人工依赖。

## 当前缺口

### 1. L1 round-trip 已落地，但当前 active gap 已不再是“有没有 runner”

这节标题保留的是本专项立项时的原始缺口表述；按当前进展回看，这个缺口已经**不是 active gap**。当前真正缺的，不再是“有没有 round-trip”，而是：

- 如何让 **`ShaderCorpus` 全量样本** 继续稳定进入 L1/L2，而不是只停在代表集
- 如何让 **`ShaderSourceDiagnostics` failure-path 样本** 也进入同一条自动化离线主回路，而不是长期依赖人工定向补喂
- 如何把这两条路径都维持在**agent 可自主执行**的范围内，不把人工枚举、人工 fresh capture、人工准备工具重新写回默认流程

### 2. canonical compare 已落地，但当前 active gap 已不再是“有没有 compare”

这条同样已经从 active gap 变成了**已关闭的历史缺口**。当前 compare 已不再只是文本 diff，而是可以专门比较 entry、地址空间、builtin / resource、CFG、instruction family 与 fast-math 风险点。

当前真正的问题已经切换为：

- L2 风险分级如何被用于**更大范围的已采集样本**，而不是长期只服务于少量代表集
- `ShaderCorpus` 全量批量结果与 failure-path 样本，如何统一进入同一套 `gate-summary / risk-report / recommendedAction` 语义
- `comparisonKey / sampleKey` 是否已经足够稳定，能避免 success-path 与 failure-path 事实混淆

### 3. 行为级测试仍然有价值，但它已不是当前 active gap

`L3` 当前仍然保留为后置升级能力；但按新的控制面优先级看，当前 active gap 已经**不是**“要不要继续扩行为 harness”，而是：

- 是否已经先把 **L1/L2 的全量已采集样本路径** 收口
- 是否已经证明默认日常构建 / 测试 / 验证仍可由 agent 独立完成
- 是否已经避免因为缺少某条自动化入口，就把人工介入重新写回默认流程

换句话说，L3 当前应继续保留为**后置升级能力**，而不是继续占据控制面中心。

### 4. 真实场景验证也仍然保留，但当前不进入目标与 TODO

虽然仓库里已经具备：

- `.gputrace` 检查
- render diff
- launch diagnostics
- MCP live 控制能力

但当前阶段不会把这些流程写回默认主线。它们只在后续用户明确决定升级到 L4 时，才重新成为 active work。

## 为什么“文本一致”不是最终目标

语义验证需要区分“文本/结构近似”与“行为/语义一致”。前者能提供强线索，但不是最终目标；因此当前更合理的顺序仍是：先做 **全量 corpus 的 canonical summary compare**，再做 **风险分级**，再只在后续确有必要时补 **行为级 / 真实场景验证**。

更细的 compare 口径与降噪策略详见 `04-L2-CanonicalCompareAndRiskGrading.md`（工作参考，当前日常推进**不必须读取**）。

## 当前最准确的现状表述

推荐统一使用下面这句话描述当前状态：

> **“语义等价”仍然是明确目标；L1/L2 的自动化离线证据已经形成，当前阶段缺的已不是 runner 或 compare 本身，而是如何把这些能力扩展到尽可能多的已采集 corpus 样本，并保证这条路径仍保持 automation-first、agent 可自主完成。因此现状仍属于“已经具备结构化语义证据”，而不是“已经拥有严格语义保证”。**
