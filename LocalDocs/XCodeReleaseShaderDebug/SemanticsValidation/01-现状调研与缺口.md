## 现状调研与缺口

## 目的

本文档承接当前语义验证现状的调研结论，回答两个问题：

1. **我们已经有什么？**
2. **为什么这些能力还不足以证明语义等价？**

主文档只保留结论与任务控制面；本文件保留当前现状、能力边界与缺口说明。若只是推进日常主线任务，优先读 `00-Dashboard.md` 与 `02-总体技术路线.md`；本文件按需阅读即可，当前日常推进**不必须读取**。

## 当前已确认的事实

### 1. 文档目标明确要求“语义等价”

前置任务优先级仍然是：

1. **语义等价**
2. **可编译**
3. **可读性**

这意味着这里的目标从来不是“源码可见 / 可编译即可”，而是尽量建立更可信的语义证据。

### 2. 当前主链路已经成熟

当前 hook、bitcode 提取、`llvm-dis`、`IRToMSLConverter`、编译、replay / corpus / runtime 工具链都已具备；语义验证专项不需要重建基础设施，重点是把已有链路收口成稳定、低心智负担、低人工依赖的默认 gate。

### 3. 当前已有的工程保证

当前已经具备：逐指令机械翻译、LLVM token 卫生检查、可编译性守门，以及 replay / compile / baseline diff / `.gputrace` 检查 / render-structure diff 等工程保障。

这些能力足以提供结构化证据，但仍不足以单独证明语义等价。

### 4. 当前阶段更适合把它当作“前置任务完成后的深化验证”来看

因此当前 active work 的重点已经不再是“有没有第一版 L3 harness”，而是**把已采集样本尽可能纳入 L1/L2 的自动化离线路径**，并确保这条路径不会重新引入人工依赖。

## 当前缺口

### 1. L1 round-trip 已落地，但还没有结构化 compare

这节标题保留的是本专项立项时的原始缺口表述；按当前进展回看，这个缺口已经**不是 active gap**。当前已经具备：

- `Scripts/ir_semantics_roundtrip_runner.py`
- `Scripts/ir_canonical_compare.py`
- `compare-summary.json / risk-report.json / high-risk-samples.json`
- `test-data/` 首轮批量结果与固定 preset 入口

因此当前真正缺的，已经不再是“有没有结构化 compare”，而是：

- 如何让 **`ShaderCorpus` 全量样本** 继续稳定进入 L1/L2，而不是只停在代表集
- 如何让 **`ShaderSourceDiagnostics` failure-path 样本** 也进入同一条自动化离线主回路，而不是长期依赖人工定向补喂
- 如何把这两条路径都维持在**agent 可自主执行**的范围内，不把人工枚举、人工 fresh capture、人工准备工具重新写回默认流程

### 2. 没有 canonical compare

这条同样已经从 active gap 变成了**已关闭的历史缺口**。当前 compare 已不再只是文本 diff，而是可以专门比较：

- 原始 IR 结构摘要 vs regenerated IR 结构摘要
- 关键 entry / 地址空间 / builtin / CFG / instruction family / fast-math 语义点
- 差异风险应该如何分级

因此现在的问题已经切换为：

- L2 风险分级如何被用于**更大范围的已采集样本**，而不是长期只服务于少量代表集
- `ShaderCorpus` 全量批量结果与 failure-path 样本，如何统一进入同一套 `gate-summary / risk-report / recommendedAction` 语义
- `gate-summary.json` 的已知 debt / 新增回归语义，是否已经足够支撑“继续停在 L2 / 升级到 L3 / 明确后置”的稳定判断

### 3. 没有行为级测试

`test-data/` 当前更像：

- lowering 模式样本
- replay/compile 的回归样本
- 编译器行为探针

而不是：

- 固定输入 → 执行 shader → 校验输出

因此它还不是“行为 gold test”。这一点到当前仍然成立；但按新的主线优先级看，当前 active gap 已经**不是**“有没有第一版行为 harness”，而是：

- 是否已经先把 **L1/L2 的全量已采集样本路径** 收口
- 是否已经证明默认日常构建 / 测试 / 验证仍可由 agent 独立完成
- 是否已经避免因为缺少某条自动化入口，就把人工介入重新写回默认流程

换句话说，L3 当前应继续保留为**后置升级能力**，而不是继续占据控制面中心。

### 4. 真实场景验证还不是严格后置 gate

虽然仓库里已经具备：

- `.gputrace` 检查
- render diff
- launch diagnostics
- MCP live 控制能力

但当前仍需继续明确：

- 何时允许进入 L4
- 哪些场景/样本属于默认代表集
- 哪些验证可自动完成，哪些必须先征求用户确认
- 若本机没有现成 live 条件，如何在不增加人工依赖的前提下合理止损

换句话说，L4 当前仍应保持“严格后置、自动化优先、人工确认兜底”的角色，而不是被写回日常默认流程。

## 为什么“文本一致”不是最终目标

语义验证需要区分“文本/结构近似”与“行为/语义一致”。前者能提供强线索，但不是最终目标；因此更合理的顺序仍是：先做 **canonical summary compare**，再做 **风险分级**，再只在高价值样本上补 **行为级 / 真实场景验证**。

更细的 compare 口径与降噪策略详见 `04-L2-CanonicalCompareAndRiskGrading.md`（工作参考，当前日常推进**不必须读取**）。

## 当前最准确的现状表述

推荐统一使用下面这句话描述当前状态：

> **“语义等价”仍然是明确目标；L1/L2 的自动化离线证据已经形成，当前阶段缺的已不是 runner 或 compare 本身，而是如何把这些能力扩展到尽可能多的已采集样本，并保证这条路径仍保持 automation-first、agent 可自主完成。因此现状仍属于“已经具备结构化语义证据”，而不是“已经拥有严格语义保证”。**

## 对本专项的直接启示

### 主优先级

当前主线与 TODO 已固定在 `00-Dashboard.md`；本页不再重复展开默认命令、样本名单或报告口径。这里仅保留结论：现阶段 active work 已经从“建设 L1/L2/L3 能力”切换为“让全量已采集样本尽可能进入 L1/L2，并把这条路径保持为最小自动化证据链”。

现阶段优先级仍然只有三层：

1. **`SV-003F`：继续让全量已采集样本尽可能进入 L1/L2**
2. **`SV-003`：继续作为长期守护约束，确保跨机器硬默认入口不回退，且新入口不引入人工依赖**
3. **`SV-004 / SV-005`：仅在 `SV-003F` 的纯离线证据仍不足，或风险只能在 runtime/live 中暴露时，才后置升级到行为级 / 真实场景验证**

补充说明：更细的旧 fail 解释、旧批量背景与契约细节统一下沉到 `07-首轮基线与历史进展归档.md` 与 `08-当前代表集与Gate契约参考.md`（均为参考，当前主线推进**不必须读取**）。

因为当前最稀缺的，不是 compare 指标，而是：

- 更低心智负担的默认入口
- 更清晰的“哪些样本已经可自动批量验证、哪些仍是待补齐缺口”
- 真正能把已采集样本规模化吃进 L1/L2、且不引入人工依赖的执行路径

### 不要过早重投入的方向

这份文档只负责解释“为什么当前仍应停在离线优先的分层路线”；若要看当前明确的止损边界与不该抢跑事项，应直接回到 `00-Dashboard.md`。这里统一只保留一个结论：**在 `SV-003F` 仍未收口前，不要把 live / GUI / 用户协助重新写回默认主线，也不要继续把最小 L3 白名单误写成当前最高优先级。**
