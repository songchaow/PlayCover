### 目标

保证每个任务结束时都形成一个**边界清晰、可回滚、可追踪**的提交，并同步沉淀必要文档。

### 每个任务必须完成的提交动作

- **代码改动**
- **测试改动**
- **文档改动**
- **单独一次 `git commit`**

### commit 范围要求

一个 commit 只对应一个任务卡。

#### 允许包含

- 本任务的实现代码
- 本任务新增或修改的测试
- 本任务相关文档更新
- 看板状态更新

#### 不允许包含

- 下一个任务的实现
- 无关重构
- 顺手修 unrelated bug
- 批量格式化整个仓库

### 推荐 commit message

建议使用以下前缀：

- **`chore(mcp): ...`**：基础设施 / 工程脚手架
- **`feat(mcp): ...`**：新增 MCP 功能
- **`test(mcp): ...`**：以测试为主的任务
- **`refactor(mcp): ...`**：不改变行为的重构
- **`docs(mcp): ...`**：纯文档任务

### 每个任务结束必须更新的文档

#### 必改

- 当前任务卡
- `06-全局任务看板.md`

#### 按需修改

- `01-总体规划与架构.md`
- `07-任务依赖与推荐执行顺序.md`
- 其他受影响任务卡

### 任务卡内必须补充的结果信息

每个任务完成后，在任务卡末尾追加或更新：

- **完成日期**
- **执行人 / agent**
- **实际改动范围**
- **测试命令**
- **测试结果摘要**
- **遗留问题**
- **commit hash**

### 全局看板必须更新的字段

至少更新：

- 状态：`TODO` / `IN_PROGRESS` / `BLOCKED` / `DONE`
- 最近一次完成说明
- commit hash
- 如有阻塞，写阻塞原因

### 建议收工流程

1. 跑测试
2. 更新任务卡
3. 更新 `06-全局任务看板.md`
4. `git status` 自检
5. `git add` 本任务相关文件
6. `git commit`

### 如果任务未完成

如果最终没有达到验收标准：

- **不要假装完成**
- 不要标记为 `DONE`
- 可以：
  - 标记为 `BLOCKED`
  - 或保留 `IN_PROGRESS`
- 必须写清楚：
  - 卡在哪
  - 还缺什么
  - 建议下一位 agent 从哪里接手
