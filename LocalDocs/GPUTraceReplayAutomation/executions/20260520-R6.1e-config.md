## 实现内容

### 用法

```
gputrace_replay_bridge config <.gputrace> [key=value ...]
```

### 支持的配置项

| Key | 默认值 | 含义 |
|-----|--------|------|
| `disableOptimizeRestores=0\|1` | 1 | 1=跳过 optimizeRestores 调用（默认） |
| `forceLoadUnusedResources=0\|1` | 1 | 1=调用 populateUnusedResources（默认） |
| `enableValidation=0\|1` | 0 | 1=启用 Metal validation layer |

### 实现架构

- 独立的 `config_replay_with_options()` 函数执行完整的初始化+replay 流程
- 每次调用创建独立的 APR pool/dataSource/objectMap/controller
- 配置项在初始化过程中的特定位置生效：
  - `forceLoadUnusedResources`: 控制是否调用 `populateUnusedResources`
  - `disableOptimizeRestores`: 控制是否调用 `optimizeRestores(controller)`
  - `enableValidation`: 写入 `g_runningValidationCI` 全局变量

### JSON 输出

```json
{
  "command": "config",
  "trace_path": "...",
  "config": {
    "disableOptimizeRestores": true,

    "enableValidation": false
  },
  "playAll_rc": 0,
  "success": true,
  "elapsed_ms": 0.254,
  "resource_count": 4
}
```

## 验证结果

### V1: 默认配置 (reference trace)

```
disableOptimizeRestores=1, forceLoadUnused=1, validation=0
playAll_rc=0, elapsed_ms=0.254, resources=4
```

### V2: 启用 optimizeRestores (disableOptimizeRestores=0)

```
disableOptimizeRestores=0
playAll_rc=0, elapsed_ms=0.042  ← 6x faster!
```

✅ **关键验证**：optimizeRestores 显著减少 replay 时间（0.254ms → 0.042ms），与 R5.4 文档记录的"168-188%性能差异"一致。

### V3: 启用 Validation

```
enableValidation=1
playAll_rc=0, elapsed_ms=0.230
```

✅ validation 层启用成功，轻微 overhead。

### V4: 大 trace (Papegames)

```
forceLoadUnusedResources=1: resources=262, time=13.86ms
forceLoadUnusedResources=0: resources=262, time=13.37ms
```

✅ 两种配置都能在大 trace 上正常工作。
