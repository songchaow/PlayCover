## RC-003：对照验证

### 一、任务目标

通过第二个真实 app，判断当前问题究竟是：

- `QQ飞车` 特有
- 某类 app 共性
- 还是当前机器 / 当前 PlayCover 环境的普遍限制

---

### 二、本轮选择的对照对象

本轮选择：

- **`原神`**（`com.miHoYo.Yuanshen`）

约束条件：

- **不允许卸载 `原神`**

因此本轮采用的是：

> **非破坏性最小链路对照验证**

只做：

- `update_app_settings(metalCaptureEnabled=true)`
- `launch_app`
- `create_session`
- `get_capture_status`
- 一次 `capture_metal_frame`

### 三、本轮关键事实

在正式验证前，先确认到：

- 最新 `PlayCover.app` 已构建、安装并启动
- GUI MCP 端口 `19820` 正常监听
- runtime 注册端口 `52741` 正常监听
- `原神` 已安装，且 `check_playtools_installed == true`

额外安装态对照：

- `原神` 已安装包的 `Info.plist`：**缺少** `MetalCaptureEnabled`
- `QQ飞车` 已安装包的 `Info.plist`：**存在** `MetalCaptureEnabled == true`

这意味着：

- `原神` 不是安装态完全干净的 capture 对照样本
- 但它依然可以用来判断：**当前现象是否只发生在 `QQ飞车`**

### 五、与 `QQ飞车` 的对照结论

本轮已可明确排除“仅 `QQ飞车` 特有”的假设。

因为 `原神` 与 `QQ飞车` 当前都表现为：

- `create_session -> ready`
- `get_capture_status` 能稳定返回
- `supports_gpu_trace=false`
- `supports_developer_tools=false`
- `failure_reason=gpu_trace_document_unsupported`
- `capture_metal_frame` 失败且无 `.gputrace`

因此：

> **当前问题更像是环境级 / 全局级限制，而不是 `QQ飞车` 单 app 问题。**

### 六、任务结论

`RC-003` 到本轮为止可以标记为 **完成**。

已回答的关键问题是：

> **`gpu_trace_document_unsupported` 不是 `QQ飞车` 特有。**

当前主线应切换为：

> **查清为什么当前机器 / 当前 PlayCover 环境下，多个真实 app 都 `supports_gpu_trace=false`。**

### 七、下一步建议

后续最值得做的不是继续换更多真实 app，而是优先做环境级定位，例如：

1. 查清 `MTLCaptureManager.supportsDestination(.gpuTraceDocument)` 的外部前提
2. 查清 `supports_developer_tools=false` 的真实含义
3. 确认当前 macOS / Xcode / Developer Tools 组合是否天然不支持 `.gpuTraceDocument`
4. 单独解释：为什么 `原神` 缺少 `MetalCaptureEnabled` key，但 live 诊断仍与 `QQ飞车` 基本一致
