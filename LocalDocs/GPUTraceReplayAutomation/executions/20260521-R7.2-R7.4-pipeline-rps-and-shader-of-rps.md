## 2. 实现要点

### 2.1 Bridge 内置 RPS swizzle（R7.2 核心）

新增 §"RPS Swizzle Capture (R7.2)"，~250 行（`Scripts/gputrace_replay_bridge.m` 中）：

- `RPSCaptureEntry` 结构体记录每对 (rps_ptr, descriptor) 的 `vfunc_ptr/ffunc_ptr/vfunc_name/ffunc_name/label/color_attachments[]/depth_format/stencil_format/raster_sample_count`
- `g_rps_captured[MAX_CAPTURED_RPS=1024]` 数组 + `g_rps_n_captured` 计数；进程级单例（合理：bridge 每次只跑一个子命令）
- `rps_install_swizzles()` 沿 `MTLCreateSystemDefaultDevice()` 类继承链向上找到具体设备实现类（如 `AGXG16XDevice`），用 `class_getInstanceMethod` + `method_setImplementation` 替换 `newRenderPipelineStateWithDescriptor:error:` 与带 `options:reflection:` 的两个变体
- 必须在 `replay_context_init()` **之前**安装：`makeController` 触发 PSO 编译；早一点也不行（`MTLCreateSystemDefaultDevice` 之前类还没具化），晚一点就漏掉
- swizzled IMP 调原 IMP 拿到 RPS 实例，再 `rps_capture_descriptor(rps, desc)` 把上下文落到表中

`cmd_pipeline` 流程改造：
1. `rps_install_swizzles()` → `replay_context_init` → `playAll`（这一步触发 PSO 编译，swizzle 落表）
2. 扫 `objectMap` 把每个 RPS_key 对应的对象指针建出 (rps_ptr → key) 关系
3. 用 `rps_find_entry(rps_ptr)` 查 swizzle 表
4. 通过 `rps_build_fn_ptr_to_key_map(objectMap)` 反向建 (fn_ptr → fn_key) 映射（来自 `objectMap.functionMap`）
5. JSON 输出每个 RPS 时附加 `vertex/fragment_function_key`、`vertex/fragment_library_key`（= fn_key - 1）、`vertex/fragment_function_name`、`color_attachment_count`、`color_attachments[]`（含 `index/format/pixelFormat/writeMask/blendingEnabled`）、`depth_format`/`depth_format_value`、`stencil_format`/`stencil_format_value`、`raster_sample_count`
6. 顶层加健康度计数：`rps_correlated_count`（pipeline 输出里有 swizzle 命中的 RPS 数）和 `rps_captured_count`（swizzle 总捕获数）

### 2.2 RPS scan 范围扩展

`cmd_pipeline` 原本用 `maxKey = max(funcMap_key) + 50` 做所有循环上界。LYSK trace 实测 max function key=439 而 RPS keys 一直延伸到 496，导致 491/495/496 等被静默截断。新增 `rpsMaxKey = maxKey + 200`，仅用于 `render_pipeline_states` 与 `compute_pipeline_states` 的扫描循环（库循环保持 maxKey），既不漏 RPS 又不增加显著探测开销（一次 `objc_msgSend` 字典查询）。

### 2.3 `shader-of-rps` 子命令（R7.4）

新增 §"Subcommand: shader-of-rps"（~250 行）：

```bash
gputrace_replay_bridge shader-of-rps <.gputrace> <rps_key> [--stage fragment|vertex] [--with-ir] [--output-dir DIR]
```

行为：
1. `rps_install_swizzles()` → `replay_context_init` → `playAll`
2. `objectMap.renderPipelineStateForKey:` 拿到 RPS；缺失返回 `error: rps_not_found` (exit 11)
3. `rps_find_entry()` 查 swizzle 表；缺失返回 `error: descriptor_not_captured`
4. 取 stage 对应的 fn_ptr；缺失（如 vertex-only RPS 求 fragment）返回 `error: stage_function_absent`
5. 经 `fnPtr2Key` 解析 `function_key`；缺失返回 `error: function_key_unresolved`
6. `library_key = function_key - 1`；用 `objectMap.libraryForKey:` 拿 library；约定失败时按偶数 key 向下扫一遍兜底
7. 拉 `libraryDataContents` 写 `library_<lib_key>.metallib`，并算 `cache_key_metallib`（PlayTools FNV-style 算法，参考 §3.1，已在 R7 文档落档）
8. 拉 `bitcodeData` 写 `library_<lib_key>.air`（很多 `_MTLLibrary` 没暴露 AIR — 输出 `ir_error: no_air_bitcode`）
9. `--with-ir` 时定位 `llvm-dis`（按 `/opt/homebrew/opt/llvm/bin/llvm-dis` → `/opt/homebrew/bin` → `/usr/local/...` → `which`）→ 跑 `llvm-dis $airPath -o $llPath` → 报 `ir_ll_path/ir_ll_size/ir_dis_path` 或 `ir_error/ir_dis_rc/ir_dis_stderr`

辅助函数：
- `compute_playtools_cache_key(NSData*)` — Objective-C 复刻 PlayTools 的 FNV-style 算法（不含尾段时退化为头段；尾段长度 `min(16, size-32)`）
- `find_llvm_dis()` — Homebrew 优先，PATH fallback；只在确实存在且可执行时返回路径

## 4. 风险与已知限制

1. **Swizzle 失效风险**：bridge 在 `MTLCreateSystemDefaultDevice()` 之后立刻爬类继承链装 swizzle。如果 macOS 升级后 Apple 把方法 IMP 提到一个我们没扫到的层，所有 R7.2/R7.4 字段会缺失但不会 crash — `rps_correlated_count` 会变为 0，是显式信号。回归手段：跑 `pipeline`，看这两个计数；或跑 `LocalDocs/OfflineSourceRecovery/scripts/rps_swizzle_probe.m` 对比。
2. **`library_key = function_key - 1` 约定**：在 LYSK trace 上 65/65 成立。bridge 实现了 fallback：约定失败则按偶数 key 向下扫一遍 `libraryForKey:` 直到找到 `MTLLibrary`，仍找不到就返回结构化 `library_not_found` 错误。
3. **AIR 覆盖率**：LYSK 96 lib 中只有 3 个暴露 `bitcodeData`（多数 `_MTLLibrary` 仅有 metallib）。`--with-ir` 在没有 AIR 的库上返回 `ir_error: no_air_bitcode` 而非崩溃；`disasm` 子命令（R7.7）将通过 cacheKey + SDI 目录 + module.bc 读出原始 LLVM 来覆盖这个缺口。
4. **进程级 swizzle 单例**：`g_rps_captured` 数组与 `g_rps_swizzles_installed` 标志是全局；同一进程多次调用 bridge 子命令不是预期使用方式（CLI 一次只跑一条），保持原状。Python wrapper 每次 `subprocess.run` 起新进程，无影响。
5. **PSO 编译之前还有什么动作**：实测 `MTLCreateSystemDefaultDevice()` 至 `replay_context_init` 之间没有触发 PSO 编译，swizzle 完全覆盖；如未来 R7.3 引入更早的 device 调用，需要重新评估安装时机。
