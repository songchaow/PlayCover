# MCPWithGUI：在 PlayCover.app 中嵌入 MCP Server

## 目标

将 `PlayCoverMCP`（当前独立的 CLI 命令行工具）的 MCP 能力**嵌入到 PlayCover.app GUI 进程内**，使用户启动图形界面时自动获得 MCP 服务，无需手动分开启动两个进程。

## 选定方案：A2（进程内 TCP Transport）

在 GUI 进程内启动一个本地 TCP 监听（如 `localhost:19820`），Agent 通过 TCP 连接与嵌入式 MCP Server 通信。

### 为什么选 A2 而不是 A1（嵌入子进程）

A1 虽然工作量最小，但存在致命缺陷：**MCP 与 GUI 运行在独立进程中，无法共享内存状态**。这意味着：

- MCP 安装了新应用 → GUI 的 `AppsVM` 不知道，列表不会更新
- MCP 修改了键位映射 → GUI 里的设置视图不会反映
- GUI 做了操作 → MCP 侧也感知不到

A2 方案让 MCP Server 和 GUI 运行在**同一进程空间**内，天然共享所有对象和状态，可以实现实时联动。

### A2 的核心收益

1. **状态共享**：MCP 操作直接触发 GUI 刷新（通过 `@Published` / `ObservableObject`）
2. **单进程部署**：不需要嵌入额外二进制，不需要管理子进程生命周期
3. **Agent 侧灵活**：TCP 比 stdio 更灵活，支持多客户端连接、远程调试等场景

## 当前状态分析

### GUI 侧（PlayCover.app）

- **入口**：`PlayCoverApp: App`（SwiftUI @main），`AppDelegate` 处理生命周期
- **应用列表**：`AppsVM`（`ObservableObject`，`@Published var apps`），通过扫描磁盘目录获取
- **刷新机制**：纯事件驱动，**没有 FSEvents 文件监听或定时轮询**
- **MCP 代码**：完全没有，GUI target 不包含任何 MCP 相关源码

### MCP 侧（PlayCoverMCP CLI）

- **入口**：`main.swift`，同步初始化所有 Service → 创建 `StdioTransport` → `transport.run()` 阻塞主线程
- **Transport**：`StdioTransport` — 读 stdin、写 stdout、`RunLoop.main.run()` 阻塞
- **核心**：`MCPServer` — 无状态的 JSON-RPC 请求分发器，与 transport 解耦
- **服务层**：各 `*Service`（AppService、InstallerService 等），直接操作文件系统，无 UI 依赖
- **源文件数**：41 个 `.swift` 文件

### 两者的关系

- **共享磁盘路径**：`~/Library/Containers/io.playcover.PlayCover/Applications/`
- **无进程间通信**：当前完全独立，互不感知
- **命名冲突**：MCP 的 `Shell`（enum）和 GUI 的 `Shell`（class ObservableObject）同名

## 核心架构决策

### 一、Transport 层

新增 `TCPTransport`，替代现有的 `StdioTransport`，在 GUI 进程内提供 MCP 服务。

| 属性 | 值 |
|-----|---|
| 监听地址 | `127.0.0.1:19820`（仅本机访问） |
| 协议 | 行分隔 JSON-RPC over TCP（与 stdio 语义一致） |
| 并发 | 支持多客户端同时连接 |
| 线程模型 | 后台 DispatchQueue / async-await，不阻塞主线程 |

### 二、MCP 代码集成方式

将 MCP 的 41 个源文件加入 PlayCover.app target 的编译（或通过共享 framework），使 `MCPServer` 及所有 Service 在 GUI 进程内可用。

### 三、服务层改造

MCP 的 Service 层当前是独立的 headless 服务（直接操作文件系统）。嵌入 GUI 后，需要让关键操作（如安装应用）完成后**主动通知 GUI 刷新**。

### 四、生命周期管理

在 `AppDelegate.applicationDidFinishLaunching` 中启动 MCP Server，在 `applicationWillTerminate` 中停止。

## 风险清单

1. **Shell 命名冲突**：MCP 的 `enum Shell` 与 GUI 的 `class Shell: ObservableObject` 同名，必须解决
2. **主线程阻塞**：当前 `StdioTransport.run()` 调用 `RunLoop.main.run()` 阻塞主线程，TCP 版必须改为后台运行
3. **线程安全**：MCP 请求在后台线程处理，回调到 GUI 刷新必须切到 `@MainActor`
4. **端口冲突**：`19820` 端口可能被占用，需要处理 bind 失败的情况
5. **签名与沙盒**：TCP 监听可能需要额外的 entitlement（`com.apple.security.network.server`）
6. **GUI 未启动时**：如果用户只想用 MCP 不想开 GUI，仍需保留独立的 `PlayCoverMCP` CLI
