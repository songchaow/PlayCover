## 2. 关键技术发现

### 2.1 `total_call_count` 字段定位

通过反汇编 `GTMTLReplayController_playTo` 函数前 0x200 字节，确认 prologue 模式：

```
+0x024: mov  x20, x0                  ; x20 = controller (arg0)
+0x020: mov  x19, x1                  ; x19 = target (arg1, w19 = w1)
+0x038: add  x23, x0, #0x5000         ; x23 = controller + 0x5000
+0x110: ldr  w8, [x23, #0x810]        ; w8 = *(controller + 0x5810)
+0x114: cmp  w8, w19
+0x118: b.cs +0x1b4                   ; HS = w8 (current) >= w19 (target) -> skip
```

**结论**：`*(uint32_t *)(controller + 0x5810)` 是 **last played call index**（不是 max）。
但因为 `playAll` 会一直跑到结尾，所以 `playAll` 完成后读这个字段就等于 trace 的 total。

LYSK trace 实测（`Scripts/call_count_probe.m`）：

```
[BEFORE playAll] *(controller+0x5810) = 0
Calling playAll...
playAll rc=0
[AFTER playAll] *(controller+0x5810) = 3425
```

并验证 `playTo(N)` 后该字段也实时变成 `N`，进一步确认其语义是"最后被 played 的 call 索引"。

注：之前 LYSK 全景调查里看到的 ~81400 是源 trace 的 raw GPU API 调用数（含每个 `setVertexBuffer:` 等），与 controller 时间序的 call index 粒度不同。controller 维度的 `total_call_count = 3425` 才是 `playTo` 的合法上限。

### 2.2 越界保护策略

| 场景 | 处理 |
|------|------|
| `--bounds` | 仅做 1 次 `playAll` 探得 `total_call_count` 后退出，不做 resource 列举 / 不做 export |
| `--playto N`，`N <= total_call_count` | 先 `playAll`（拿 max）→ `rewind` → `playTo(N)`，正常输出 |
| `--playto N`，`N > total_call_count` | **不调用 `playTo`**，直接返回 `{"error":"playto_out_of_range","max":...}`，exit 12 (`EXIT_PLAYTO_OOR`) |
| 默认（无 `--playto`） | 等价于以前的 `playAll`，但额外报告 `total_call_count` 与 `last_call_index` |
| 任何 SIGSEGV/SIGBUS 异常 | `setjmp` + `sigaction` 兜底，捕获后将 `replay_signal` 字段写入 JSON 并以错误码退出，不 crash 进程 |

兜底 SIGSEGV 处理纯属保险 — 在新增的 OOR 校验已经避免的前提下，当前 LYSK trace 的所有越界 / 边界用例都不会触发它，但留作 framework 行为变化的安全网。

## 5. 与 R7 后续 chunk 的衔接

R7.2（`pipeline` 输出加 RPS↔shader 关联）将复用 R7.1 在 `replay_context_init` 之前安装 method swizzling 的窗口。R7.1 没有动这部分初始化逻辑（只在 `cmd_replay` 内做控制流变更），所以下一步可以无冲突地在 `replay_context_init` 入口前加 swizzle hook。

`total_call_count` 暴露后，R7.3 (`frame-list`) 可以把每个 encoder 的 `[first_call_index, last_call_index]` 范围直接对照 `total_call_count` 检查闭合性。

## 6. 已知限制 / 后续

- `replay --playto N` 现在会先跑一次完整 `playAll` 再 `rewind`，比纯 `playTo(N)` 多一次全帧开销（LYSK trace ~9ms，可忽略）。日后若发现某 trace 的 `playAll` 代价大且 `--playto N` 用得很重，可考虑在 controller 内部做"二分而不全跑"的探边界路径，但目前没必要。
- `+0x5810` 偏移在 `GTMTLReplayController_playTo` 当前 macOS 版本下稳定。系统升级后若反汇编 prologue 模式变化，需要更新 `CONTROLLER_LAST_CALL_INDEX_OFFSET` 常量；保留的 `Scripts/call_count_probe.m` 可一键回归验证。
- SIGSEGV 兜底用的是 `longjmp` 跳过有问题的调用 — 这之后 controller 内部状态可能被破坏，所以 R7.1 在 OOR 校验通过的前提下，不会触发兜底；兜底仅作"框架真崩了"的最后一道墙。
