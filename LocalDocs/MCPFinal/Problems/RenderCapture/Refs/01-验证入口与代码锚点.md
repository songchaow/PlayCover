## Render Capture：验证入口与代码锚点

### 一、当前已知验证入口

#### 1. GUI / MCP 基础入口

- `PlayCover.app`
- GUI 内嵌 MCP HTTP：`http://127.0.0.1:19820/mcp`
- runtime 注册端口：`52741`

#### 2. 推荐验证层次

优先按下面顺序理解问题：

1. GUI / MCP 是否正常启动
2. 真实 app 是否能 `launch_app`
3. `create_session` 是否到 `ready`
4. `get_capture_status` 的核心状态字段是否合理
5. 若 `supports_gpu_trace=false`，继续看新增诊断字段
6. `capture_metal_frame` 是否真的落盘 `.gputrace`

#### 3. 当前真实测试对象

- 主对象：`QQ飞车`（`com.tencent.tmgp.speedmobile`）
- 对照候选：`原神`（`com.miHoYo.Yuanshen`）

### 六、当前最关键的已知事实

截至 2026-03-31，已知：

**截帧已打通（QQ飞车）：**

- `QQ飞车` 能稳定 `create_session` → `ready`
- `metalCaptureEnabled=true` + `DYLD_INSERT_LIBRARIES=/usr/lib/libmtlcapture.dylib` 注入后，`supports_gpu_trace=true`
- `capture_metal_frame` 成功落盘 124MB `.gputrace`

**兼容性问题（原神）：**

- `原神` 在 `metalCaptureEnabled=true`（启用 `DYLD_INSERT_LIBRARIES` 注入）时启动即崩溃
- 崩溃原因：`GPUToolsCapture.MakeLayerInfos` 在 `CAMetalLayer` 初始化时调用了原神不响应的 selector
- `原神` 当前已临时关闭 `metalCaptureEnabled`
- 下一步方向：RC-009 延迟注入方案（`dlopen` 替代 `DYLD_INSERT_LIBRARIES`）

**当前测试对象兼容性矩阵：**

| App | metalCaptureEnabled | 启动 | 截帧 | 备注 |
|---|---|---|---|---|
| QQ飞车 | true | ✅ 正常 | ✅ 成功 | 首个成功样本 |
| 原神 | true | ❌ 崩溃 | — | `GPUToolsCapture` hook 不兼容 |
| 原神 | false | ✅ 正常 | ❌ 不可用 | 截帧被 settings 禁用 |
