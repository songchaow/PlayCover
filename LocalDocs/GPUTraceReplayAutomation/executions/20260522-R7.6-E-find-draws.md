# R7.6-E: `find-draws` — 按 label / shader 名 / RPS key 反查 draw 列表

**执行时间**：2026-05-22  
**性质**：wrapper-only，bridge 零变更  
**耗时**：< 0.3 天

## 动机

用户在 Xcode GUI Frame Debugger 看到的是 shader 名 / RPS label 字符串（如 `SkinMakeupNew`），但 CLI 工具链入口 `shader-of-drawcall` 需要整数 `draw_index`。用户实战中（`locate_shader.py`）绕过了工具链自行扫描 device-resources blob 来定位 shader。**根因是入口阻抗**——不是工具能力不足。

### CLI 接口

```bash
python3 gputrace_replay_wrapper.py find-draws <trace> \
    [--by-label SUBSTR] [--by-shader-name SUBSTR] [--by-rps-key K] \
    [--limit N] [--show-first] [--stage fragment|vertex] \
    [--with-ir] [--with-uniforms] [--output-dir DIR]
```

### 模块接口

```python
bridge.find_draws(
    trace_path,
    by_label="SkinMakeupNew",
    show_first=True,
    show_first_with_ir=True,
    show_first_with_uniforms=True,
) -> FindDrawsResult
```

### 核心设计决策

1. **Bridge 零变更**：`frame-list` 输出已含 `rps_label`；`pipeline` 输出含 `vertex_function_name` / `fragment_function_name`。wrapper 做内存 join + 过滤。
2. **`--by-label` 只走 frame-list**（单次 replay）；`--by-shader-name` 额外调一次 `pipeline`（也只有一次 replay，bridge 共享 context）。
3. **过滤条件 AND 组合**：多个条件同时指定时全部满足才命中。
4. **`--show-first` 一步到位**：找到第一条命中后自动联动 `shader-of-drawcall`，实现 GUI → CLI 的零步跳转。
5. **不引入正则匹配**（YAGNI）：仅子串，大小写不敏感。

## 已知局限

- `vertex_function_name` / `fragment_function_name` 仅在 `--by-shader-name` 时填充（避免不必要的 `pipeline` 调用开销）
- Unity/HLSLcc 生成的 shader 全叫 `xlatMtlMain`，`--by-shader-name` 在此类 trace 上实际无区分度；`--by-label` 是更好的入口
- 不解决 "GUI RPS 指针 0x... → replay RPS_key" 反查（地址空间不同，技术不可达）
- 不做正则匹配，仅子串
