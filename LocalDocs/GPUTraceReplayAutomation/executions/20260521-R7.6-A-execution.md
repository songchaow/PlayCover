## 3. 设计决策记录

| 决策 | 取舍 |
|------|------|
| **bindings 默认 ON** | 与 `--with-draws` 默认风格一致；用户拿到的 `frame-list` 输出最完整。`--no-bindings` 给体积敏感场景留出口 |
| **per-draw fixed-size 表 + sparse emit** | 内存 ~280 bytes/draw（244 draws 即 ~70KB，可接受）；emit 阶段稀疏，JSON 只含 set 的槽位。比"动态 binding 列表 + per-set vector push"实现简单且无内存碎片 |
| **emit 时一次性反向构建 (ptr → resource_id) 字典** | 替代每次 binding emit 线性扫 `objectMap.resources`；LYSK 686k 次比较 → 686k 次 O(1) NSValue 查找，emit 阶段从 ~600ms 降至 ~50ms |
| **sampler 不解析 resource_id** | sampler state 不在 `objectMap.resources`；只 emit ptr 作诊断身份。R7.6-A 不为 sampler 单独建 key range（独立工作量） |
| **不直接更新 ShaderOfDrawcallResult** | 保持本任务最小变更原则；R7.6-C 联动延后到 R7.6-B 一并处理 |
| **inline buffer 只记 size、不复制 bytes** | 避免污染 binding 表；LYSK 0 inline 用例验证不到字节正确性。如未来 trace 用 setVertexBytes，加 `--with-inline-bytes` flag |
| **测试 draw-shape 断言用 `[ "$BIND_DRAW_COUNT" -gt 0 ]` 守卫** | 与 R7.3 的"已知盲点"原则一致；不重复 R7.5-B 的 trace-shape 修正责任 |
